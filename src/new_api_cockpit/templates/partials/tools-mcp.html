账户 MCP：余额、用量与 KEY 管理

使用本人的用户 API PAT 认证，不调用模型。KEY 管理能力与插件一致；不提供 Claude/Codex 配置草稿。

  1. 1

    创建用户 API PAT

    打开 安全与访问，创建本人的 API 访问令牌并设置有效期。余额需要 profile:read，用量另需 usage:read；KEY 列表需要 api_key:read，申请、删除、改组另需 api_key:write，读取完整密钥另需 api_key:reveal。按需要授权，仅查余额不用授予 KEY 权限。本页不读取、代建或展示你的 PAT。

  2. 2

    添加远程 HTTP MCP

    选择支持 Streamable HTTP 及自定义 Bearer 凭据的客户端，地址使用本步的 /cockpit/mcp，不是 /v1。Authorization 为 Bearer 加你的用户 PAT。不支持自定义请求头、只支持 OAuth 的客户端不能直接使用此静态 PAT 配置。

    本网站 MCP 地址
    /cockpit/mcp
    账户 MCP 配置只含占位符，不会填入模型 KEY

    Codex 的 NEW_API_USER_PAT 怎么设置？

    这是账户 MCP 的专用凭据，与 auth.json 中调用模型的 OPENAI_API_KEY 分开。以下在你自己的终端交互输入 PAT，不把明文写入历史；配置后从同一终端启动 Codex。桌面或 IDE 需通过其受信任的启动环境提供该变量，终端变量不会自动传给已打开的桌面进程。

    # macOS / Linux（Bash / Zsh）
printf '请输入用户 API PAT: '; read -r -s NEW_API_USER_PAT; printf '\n'; export NEW_API_USER_PAT

# Windows PowerShell
$env:NEW_API_USER_PAT = [System.Net.NetworkCredential]::new('', (Read-Host '用户 API PAT' -AsSecureString)).Password
  3. 3

    使用账户和 KEY 工具

    保存配置后重连 MCP。get_balance 查询余额；get_usage 查询用量，默认北京时间今天到现在，自定义区间最长 31 天。KEY 工具有 list_keys、list_key_groups、create_key、delete_key、change_key_group、reveal_key。先查询本人 KEY 和可用分组，再使用返回的 ID 操作。旧配置如果只启用了两项查询工具，需要更新 enabled_tools。

    例如：“列出我的 KEY 和可用分组”“申请一个叫 Codex 的 KEY，auto 分组，不单独限额”“把 KEY 123 改到 auto 分组”。删除或读取完整密钥应明确说明具体 KEY。每次修改前后查询，结果不明时不会自动重发，也不用去网页核对。

只能操作本人账户和 KEY，不提供充值、修改账户余额、查看他人或读取提示词。完整 KEY 仅在显式调用 reveal_key 时返回，请勿分享包含密钥的对话。改组使用 New API 官方 PUT，不能保证与同时发生的模型消费原子隔离。金额按 quota / 500000 换算；用量按模型最多列 20 项，总计覆盖全部。撤销或过期的 PAT 下次请求即失效，请使用 HTTPS。

本服务兼容 2025-03-26、2025-06-18 和 2025-11-25 协议，采用 MCP Streamable HTTP 的 JSON 响应方式，不提供旧式 SSE 地址或 OAuth 登录。
