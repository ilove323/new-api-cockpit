接入配置说明

模型调用 KEY
从上方“本人令牌”选择，通常以 sk- 开头。用来配置下方客户端并调用模型，消费记在你的账户。页面只显示占位符，明确点击含 KEY 复制按钮才读取该令牌。
用户 API 访问令牌（PAT）
从 New API 的“安全与访问” 创建，供账户 MCP 查询本人余额和用量。它不是模型 KEY；新式 PAT 通常以 nap_ 开头。不要互换，也不要把管理权限交给客户端。
服务地址
各客户端的地址格式不同：有的填站点根地址，有的需要 /v1，有的要填完整接口路径。示例按当前站点的地址和端口生成，按对应步骤填写即可，无需再补 /v1。
接口协议
本站提供 Chat、Responses 和 Anthropic Messages 接口。按教程选择客户端支持的协议，模型也须支持该接口，不能只凭模型名称判断。读取模型列表不会生成内容；连接测试、任务和对话按实际用量计费。
配置文件
修改前保留备份，只合并需要的字段，不覆盖整份配置。文件名不要多出 .txt 后缀；JSON 不支持注释和尾随逗号，TOML 顶层字段放在表头之前。保存后完全退出客户端再打开。

      官方资料

        账户 MCP：查询本人余额与用量

        独立于模型接入，不需要选择上方的模型令牌，也不会调用收费模型。

        1. 1

          创建最小权限的用户 API PAT

          打开 安全与访问，创建本人的 API 访问令牌。勾选 profile:read（读取本人资料和余额）与 usage:read（读取本人用量），设置合理有效期。不授予管理或写权限。本页不读取、代建或展示你的 PAT。

        2. 2

          添加远程 HTTP MCP

          选择支持 Streamable HTTP 及自定义 Bearer 凭据的客户端，地址使用本步的 /cockpit/mcp，不是 /v1。Authorization 为 Bearer 加你的用户 PAT。不支持自定义请求头、只支持 OAuth 的客户端不能直接使用此静态 PAT 配置。

          本网站 MCP 地址
          /cockpit/mcp
          账户 MCP 配置只含占位符，不会填入模型 KEY

          Codex 的 NEW_API_USER_PAT 怎么设置？

          这是账户 MCP 的专用凭据，与 auth.json 中调用模型的 OPENAI_API_KEY 分开。以下在你自己的终端交互输入 PAT，不把明文写入历史；配置后从同一终端启动 Codex。桌面或 IDE 需通过其受信任的启动环境提供该变量，终端变量不会自动传给已打开的桌面进程。

          # macOS / Linux（Bash / Zsh）
printf '请输入用户 API PAT: '; read -r -s NEW_API_USER_PAT; printf '\n'; export NEW_API_USER_PAT

# Windows PowerShell
$env:NEW_API_USER_PAT = [System.Net.NetworkCredential]::new('', (Read-Host '用户 API PAT' -AsSecureString)).Password
        3. 3

          询问并核对结果

          保存配置后重连 MCP，确认能看到 get_balance 和 get_usage。可询问“我的余额还剩多少”“今天用了多少 Token”。默认查询北京时间今天到现在；自定义时间区间最长 31 天，结束时刻不包含。无论账号是不是管理员，都只能查自己的数据。

        MCP 只返回本人账户和消费汇总，不提供充值、修改额度、读取模型 KEY、查看他人或读取提示词的工具。金额沿用 Cockpit 的 quota / 500000 账面单位，不自动换汇；按模型最多列出 20 项，总计仍覆盖全部模型。撤销或过期的 PAT 下次请求即失效。请通过 HTTPS 使用远程 MCP。

        本服务兼容 2025-03-26、2025-06-18 和 2025-11-25 协议，采用 MCP Streamable HTTP 的 JSON 响应方式，不提供旧式 SSE 地址或 OAuth 登录。

        遇到问题怎么办？

        没有令牌，或令牌不可用

        前往 New API 的令牌管理 检查启用状态、有效期和额度。只会列出本人的令牌；管理员也不会在这里调用其他人的 KEY。

        读取模型失败 / IP 不在允许列表

        查看上方的后台错误。令牌的模型权限、分组、IP 允许列表等限制不会绕过，也不会改用全站模型列表。按后台说明调整本人令牌的设置，确认后手动重新读取。

        401 / 403：登录或权限问题

        401 时重新登录；403 时检查所选令牌是否有该模型的权限及 IP 限制。切换账号后请重新加载本页，不要继续使用旧配置。

        404 / model not found：地址、模型或协议不匹配

        模型名称要与列表一致，包含大小写。检查工具要求的是根地址、/v1 地址还是完整接口路径；按教程选择协议。

        429 / 额度不足 / 连接超时

        检查令牌额度、账户余额及服务限制，稍后再手动操作。超时不代表请求未到达；请先核对工具记录和用量，不要反复发送。

        Codex 还是要求登录，或配置文件没生效

        确认 config.toml 和 auth.json 位于同一个 CODEX_HOME，默认是 ~/.codex；config.toml 顶层设置 cli_auth_credentials_store = "file"，提供商表内设置 requires_openai_auth = true。auth.json 使用严格 JSON，OPENAI_API_KEY 中是模型 KEY。备份旧登录后再更换认证文件，检查项目配置、环境变量、启动参数和组织策略是否覆盖了设置。

        MCP 报 401 / 403，模型 KEY 明明能用

        模型 KEY 与用户 API PAT 是两种凭据。401 检查 PAT 是否有效、是否被撤销、是否误填了 sk- 模型 KEY 或网页登录 JWT；403 检查 profile:read 和 usage:read 权限、账号启用状态及同源限制。不要在 URL 查询参数或工具参数中传 PAT、用户 ID 或上游地址。

        剪贴板不可用

        使用 HTTPS 或本机的安全页面，并允许浏览器访问剪贴板。若复制被阻止，可手动选中预览中的配置复制，再在工具内填写 KEY。
