# New API Cockpit 账户与 KEY

在 VS Code 底部状态栏直接查看账户名和可用余额，侧栏查看累计消费、请求数和更新时间；余额下方有独立的 **KEY 管理**分区，可申请、复制、删除本人 KEY 和切换分组。不调用模型。

**只需要 New API 站点和本人的用户 API PAT，不需要安装 new-api-cockpit，也不需要 MCP。** 余额直接读取 `/api/user/self`，KEY 管理直接使用 New API 本人接口。Cockpit 网站只是插件的一个下载入口。

## 安装

需要 VS Code 1.95 或更高版本，支持 Windows、macOS 和 Linux 桌面版。远程 SSH / Dev Container 工作区中，插件在本机界面侧运行，站点需要从本机可访问；暂不提供浏览器版插件。

1. 登录网站，打开 **文档 → 辅助工具** 下载当前镜像内的 VSIX；也可从对应 GitHub Release 下载 `new-api-cockpit-balance-0.4.2.vsix`。Release 的附件直接从发布镜像导出，与网站下载相同。已装旧版时直接安装新版覆盖，原连接配置保留。
2. 打开 VS Code 扩展面板，点击右上角 `…` → **从 VSIX 安装**，选择该文件。
3. 点击左侧 **Cockpit** 图标，或点击右下角的账户余额。

也可以用命令行安装：

```sh
code --install-extension new-api-cockpit-balance-0.4.2.vsix
```

## 配置账户

### 1. 创建用户 API PAT

在站点的 **安全与访问**（`/security`）创建本人用户 API 访问令牌，授予 **`profile:read`** 权限并设置到期时间。只查余额，不需要 `usage:read`。

如要管理 KEY，还需按功能勾选：

| 权限 | 用途 |
| --- | --- |
| `profile:read` | 账户余额、本人可用分组 |
| `api_key:read` | 本人 KEY 列表与配置 |
| `api_key:write` | 申请、删除 KEY、切换分组 |
| `api_key:reveal`（可选） | 点击“复制完整 KEY”或“配置 Claude / Codex”时读取密钥 |

旧版只查余额的 PAT 不会自动获得这些权限。请在网页准备好包含所需权限的 PAT，再执行“配置账户连接”替换。没有管理权限不影响原有余额功能。

这里使用用户 API PAT（新式令牌通常以 `nap_` 开头），**不是**“管理我的 KEY”中的 `sk-` 模型密钥，也不是登录 JWT、账号密码或浏览器 Cookie。管理员 PAT 也只能查询它所属的账户。

### 2. 填写连接

打开命令面板，执行 **Cockpit 余额：配置账户连接**，依次填写：

- **站点地址**：例如 `https://gateway.example.com`，升级前保存的 `/cockpit/mcp` 地址也会自动识别为同一个站点，但不会再请求 MCP。
- **用户 API PAT**：上一步创建的令牌，输入框隐藏内容。

保存后查询余额；如果该站点还处于刷新冷却期，会显示最早可刷新时间。地址与 PAT 一起放入 VS Code 密钥库，不写入工作区、`settings.json`、日志或安装包。更换地址时必须重新输入 PAT，不把旧凭据自动发到新站点。

服务器只需提供 New API 的 `/api/user/self`、`/api/status` 及本人令牌接口。New API 验证 PAT 和权限；无需 Cockpit 服务、MCP 开关或额外端口。

远程地址必须使用 HTTPS，证书验证不能关闭；HTTP 只允许本机 `localhost`、`127.0.0.1`、`[::1]` 测试。请求不跟随重定向，不把 PAT 转发到其他地址。网络请求使用 VS Code 扩展宿主的内置 `fetch` 与连接池，沿用宿主的代理和证书配置；插件不修改全局代理或关闭证书校验。

## 查看和刷新

- **底部状态栏**：显示 `demo-user · 可用余额 123.45`，点击打开账户侧栏；账户名和余额来自同一次查询，不增加请求。查询失败时显示账户名和“上次余额”，悬停可看更新时间及错误原因。
- **账户侧栏**：显示用户名、余额、累计消费、累计请求、更新时间和金额口径。右上角可刷新、重新配置或删除连接。
- **自动刷新**：默认 **15 分钟**。在设置中搜索 `newApiCockpitBalance.refreshIntervalMinutes`，可选 `0`、`15`、`30`、`60`；`0` 表示只手动刷新。

金额使用 New API 返回的整数额度和 `quota_per_unit` 精确换算，不自行加上人民币/美元符号、换汇或换算成 Token。很小的余额也不会被四舍五入显示为零。当前版本只查询余额和账户累计值，不提供日期区间用量及按模型汇总。

### 余额请求频率

- 每次刷新读取一次 `/api/user/self`。首次连接另读一次公开 `/api/status` 确定额度单位，该单位在当前连接内缓存一小时；到期后下次余额刷新才更新。公开状态请求不携带 PAT，不额外读取模型 KEY。
- 手动刷新至少间隔 **60 秒**，连点和并发刷新合并，不重复请求。
- 同一 VS Code 用户配置下，多窗口和重启共享按站点记录的冷却时间；文件只有时间戳，不保存账户资料、余额或 PAT。删除、重配连接也不绕过该冷却。
- 收到 **429** 不立即重试。支持秒数或 HTTP 日期形式的 `Retry-After`；至少暂停 **15 分钟**，服务端要求更久则继续等待。等待期间手动点击和自动定时器都不会发请求，暂停记录在重启后仍有效。
- 单次请求最多等待 **10 秒**；失败不自动重试。网络失败保留的数值明确标为“上次余额”，不把它冒充刚查询的结果。
- **401 / 403** 清除已显示的余额并暂停自动刷新，避免对失效凭据反复查询；修正 PAT 后重新配置连接。

这些限制用于降低请求频率，不能保证站点永远不返回 429；同一出口的其他客户端流量仍会占用服务端限额。

### 删除连接

执行 **Cockpit 余额：删除账户连接**，确认后移除本机保存的地址、PAT 和内存中的账户显示，不修改服务器账户，也不撤销服务器上的 PAT。需要停用 PAT 时，去站点的安全与访问页面撤销。

## KEY 管理

左侧 Cockpit 内，**账户余额**与下方的 **KEY 管理**是两个原生分区，中间有独立的分隔条。KEY 区不会随余额定时刷新；首次点击“载入我的 KEY”或右上角刷新按钮再读取。

- **申请 KEY**：点 KEY 区右上角 `＋`，填写名称、选择分组、额度和有效期，确认后申请。有限额度按站点账面单位输入；不单独限额也仍受本人账户余额限制，不会给账户充值。
- **按组查看**：列表按实际分组归类；每页最多 50 个，更多 KEY 手动翻页，不后台扫描全部页。
- **切换分组**：悬停某个 KEY 点文件夹图标，或右键“切换 KEY 分组”，选择当前账户可用分组后直接执行，不再弹出二次确认。不会按 GPT、模型名称或固定组过滤。这里的“分组”指 New API 路由组，不创建全站新分组。
- **删除 KEY**：点垃圾桶图标或右键删除，确认后执行。删除会使使用它的客户端无法继续调用。
- **复制 KEY**：点复制图标，需要 `api_key:reveal`。第一次复制时读取完整密钥，之后从当前连接的内存缓存复制，不重复读取。加载列表、余额刷新和申请成功后都不会自动读取完整密钥，也不把完整 KEY 保存到文件、日志或列表状态。
- **配置 Claude / Codex**：点 KEY 旁的齿轮或右键选择同名操作，生成可编辑、未保存的客户端配置草稿，详见下节。也可从命令面板执行，再选择本人 KEY。

当前上游提供的是覆盖更新接口，插件会在操作前读取最新配置，保留读取到的额度、有效期、模型限制、IP 限制和账户额度查询开关。尽量避免在该 KEY 正在计费调用或被其他客户端编辑时改组，以免并发覆盖额度。插件不要求填写“已经暂停”或跳转网页。切到 `auto` 时跟随站点默认范围，不开启跨组重试；不增加模型调用。

### 缓存和更新

- 列表的已读页、可用分组和已复制的完整 KEY，取到后保留在当前连接的内存中，**不设自动过期时间，不后台更新**。展开分组、返回已读页、再次打开分组选择或复制同一个 KEY 都复用缓存，余额定时刷新也不读取它们。
- 点击 KEY 区的 **刷新** 才重新读取列表，并清空其他页、分组及完整 KEY 的旧缓存；分组或完整 KEY 下次用到时再读取。未读过的页和数据首次使用时按需获取。
- **新建、删除、改分组都按“查询一次 → 执行修改 → 查询一次”顺序执行**，两次查询都不走旧列表缓存；新建前查询第一页，其他修改前查询当前页，操作后查询第一页。仅在回执丢失且第一页不能确定结果时补查后续页，不重发写请求。新建以唯一新增的匹配记录核对，并发新增导致歧义时不假称成功。操作前查询失败或用户取消时不执行修改。
- 改分组直接使用操作前查询返回的最新额度、有效期和限制，不再为同一个 KEY 多发一次配置查询，也不读取完整密钥。删除成功同时移除该 KEY 的完整密钥缓存。
- **KEY 查询和修改都没有插件设定的时间间隔限制**。手动点击查询立即发起请求，前一个动作结束后可立即做下一个；只合并尚未完成的查询、阻止同一时刻重复写入，不添加 60 秒、5 秒或 15 分钟的等待。
- New API 自身仍可能返回 429。插件显示服务端错误，不自动重试，也不因这次 429 给后续手动 KEY 查询加冷却时间。余额的自动刷新与等待规则独立，不阻止 KEY 查询。
- 更换账户连接、删除连接或关闭扩展会清空内存缓存。缓存不写磁盘，重新打开扩展后仍需手动载入 KEY，不会自动获取。

申请、删除或改组遇到超时、断线、无效响应时，结果可能已生效。**结果确认由插件自动完成，不要求去网页核对，也没有核对解锁按钮或全局操作锁。** 删除或改组的回执丢失后，如果操作后查询已证明目标 KEY 删除或已切到指定分组，就直接显示成功；实际记录没有变化则显示未生效，不把收到 HTTP 200 当成业务成功。仍无法确定时显示错误和最新列表，不自动重复写入，也不拦截之后的手动操作。申请回执丢失时，不会凭同名 KEY 猜测成功或自动再次申请。

本人接口和 PAT 权限按 New API `v1.0.0-rc.46` 核对。管理员 PAT 也只操作其所属用户的 KEY，不访问管理员全站 KEY 接口。接口参考：[本人 KEY 路由与权限](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.46/middleware/access_token_routes.go)、[KEY 处理与所有者检查](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.46/controller/token.go)。

## 配置 Claude Code / Codex

### 打开草稿

1. 在 **KEY 管理**中选中要使用的 KEY，点齿轮，或右键 **配置 Claude / Codex**。
2. 选择 **Claude Code** 或 **Codex**。站点地址沿用当前账户连接，填入的是所选模型 KEY，不是用户 API PAT。
3. 查看打开的文本草稿，可继续编辑。草稿上方会显示客户端、文件名和保存目标；底部状态栏也会显示当前草稿。
4. 按 **Ctrl+S**（macOS 为 **⌘S**），或点击草稿上方、编辑器右上角的保存按钮，保存到显示的目标路径。不需要手工复制、粘贴或输入路径。
5. Codex 的**两份草稿都需要保存**，然后重载对应客户端。插件不自动重启客户端或发送模型测试请求。

**打开草稿不改原文件，开启自动保存也不例外。** 放弃时关闭草稿并选择不保存；未保存的内容不会成为客户端配置。保存快捷键只在这些配置草稿获得编辑焦点时接管，其他文件的保存行为不变。如果快捷键被其他扩展覆盖，使用草稿上的保存按钮。原生“另存为”仍由 VS Code 处理，选择的路径由你决定；要覆盖预定路径，请使用本插件提供的保存入口。

### Claude Code

- 选择 Claude 扩展实际使用的 **VS Code 用户 `settings.json`**。支持默认用户配置、用户配置目录中的其他 Profile，以及显式选择其他用户配置文件；不修改项目的 `.vscode/settings.json`。
- 覆盖 `claudeCode.environmentVariables` 中的 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN`，根地址不加 `/v1`。清空冲突的 `ANTHROPIC_API_KEY`，关闭旧 Bedrock / Vertex / Foundry 路由开关，并启用 `claudeCode.disableLoginPrompt`。
- 同名连接变量只留一份；保留其他环境变量、模型选择、权限设置，以及 VS Code 的其他设置和注释，不强行指定 Claude 模型。

### Codex

- 使用本机 `CODEX_HOME` 指定的目录；未设置时使用用户主目录下的 `.codex`。不会放到项目目录或扩展安装目录。
- **`config.toml`**：覆盖顶层 `model_provider`、`cli_auth_credentials_store` 和 `model_providers.newapi`，使用本站 `/v1`、Responses 协议和文件认证。已有 `forced_login_method` 时切换为 `api`；不改默认模型、MCP、推理强度或权限设置，保留其他 Provider 和无关内容的格式、注释。
- 同名 `newapi` Provider 整段替换，移除其旧 `env_key`、命令认证或认证请求头，不在同一份配置里追加重复 Provider。
- **`auth.json`**：替换成 `auth_mode: apikey` 和所选模型 KEY，不混入旧 ChatGPT OAuth token / refresh 信息。这会切换共用该目录的 Codex CLI / IDE / 桌面客户端认证；两份文件不是一次原子保存，请都保存后再使用。
- 现有 Profile、项目配置、环境变量、启动参数或组织策略可能有更高优先级；草稿不会清除它们，也不会绕过组织限制。

### 保存与隐私

- 完整 KEY 只在主动执行配置操作时按需读取，复用“复制 KEY”的当前连接内存缓存；不额外刷新列表、不读取模型目录、不调用模型，也不写剪贴板。
- 现有配置格式错误、字段重复或文件已有未保存修改时，先报错，不生成可能丢失旧配置的覆盖内容。已有同目标草稿时不覆盖你正在编辑的草稿。
- 手动保存前再次校验格式及原文件内容；若原文件已在别处变更，停止覆盖并保留草稿。手动保存使用临时文件后原子替换，不在生成草稿时创建目录；含 KEY 的配置在 macOS/Linux 以仅当前用户可读写的 `0600` 权限保存。
- 草稿和保存后的客户端配置会包含明文 KEY，这是客户端配置所需。不要分享、提交仓库或同步含 KEY 的用户设置。插件不另存草稿或记录内容，但 VS Code 的 Hot Exit、备份或其他扩展可能保留/读取编辑器内容。重载插件前请先保存；重载后恢复的普通未命名文档不再保留本插件的目标路径关联。
- 目前此功能面向**本机 VS Code 窗口**。远程 SSH、WSL 或容器窗口，以及 Windows 下启用 Codex 在 WSL 内运行的设置时，会提示不支持，不会猜测远程用户主目录或误改本机配置；原有余额和 KEY 管理不受影响。

依据：[Claude Code VS Code 配置](https://code.claude.com/docs/en/vs-code#extension-settings)、[Codex Provider](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers)、[Codex 认证存储](https://learn.chatgpt.com/docs/auth#credential-storage)。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 401 | 确认使用用户 API PAT，未过期或撤销，不是模型 KEY |
| 403 | 按提示补齐对应 PAT 权限；余额需 `profile:read`，KEY 列表/写操作/复制分别需 `api_key:read` / `api_key:write` / `api_key:reveal` |
| 404 | 检查 New API 站点地址、接口版本和反向代理路径 |
| 余额 429 / 等待刷新 | 等到余额区显示的最早可刷新时间 |
| KEY 接口 429 | New API 自身限流；插件不自动重试、不添加手动查询冷却，可稍后手动查询 |
| `ECONNRESET` / `UND_ERR_SOCKET` | 连接中途断开，不等于证书失效；先更新插件，再检查 VS Code 的代理及本机网络链路 |
| HTTPS 证书校验失败 | 按显示的证书错误码检查有效期、域名及证书链；插件不会跳过证书验证 |
| `ENOTFOUND` / `EAI_AGAIN` | 本机域名解析失败，检查 DNS 和代理配置 |
| 密钥库保存失败 | 检查 VS Code 和系统密钥库，不会退回明文存储 |
| 草稿按保存没有反应 | 使用草稿上方或编辑器右上角的“保存配置草稿到原路径”；检查是否被其他快捷键覆盖 |
| 原配置已变化 / 已有草稿 | 保存或放弃当前草稿后重新生成，不会后台覆盖原文件或旧草稿 |

## 开发与打包

本目录源码独立维护；Cockpit 镜像构建时会打包本插件，将 VSIX 与校验清单作为 Python 包数据一并分发，运行层不包含构建工具。构建需要 Node.js 22 或更高版本；安装后的插件不需要另装 npm 依赖。JSONC / TOML 解析器由 esbuild 打包到运行文件，许可证随 `THIRD_PARTY_NOTICES.txt` 提供；其余开发依赖不进安装包。

打包工具的间接依赖 `@azure/msal-node` 固定为 `7.1.0`，避开 [GHSA-xcx6-jx8p-x3h5](https://github.com/advisories/GHSA-xcx6-jx8p-x3h5) 的受影响版本。这里只使用 `vsce` 的本地打包功能，不配置 Azure / Marketplace 登录，也不把这些开发依赖放入安装包。

```sh
cd vsix
npm ci --ignore-scripts
npm run check
npm test
npm run package
```

安装包生成在本目录，打包仅包含清单、编译后的运行文件、图标、许可证和用户文档，不带源码测试、开发依赖目录、凭据或本地配置。`dist/`、`node_modules/` 和生成的 `.vsix` 不提交。

`npm test` 覆盖直接账户查询和额度单位缓存、HTTPS/重定向边界、余额限流等待与跨窗口/重启冷却、账号切换隔离、金额精度，以及虚构 New API 的 KEY 申请/删除/改组、缓存不按时间失效、手动查询无冷却、每次修改前后各查一次、完整 KEY 显式读取及丢失回执后的自动结果确认。KEY HTTP 联调校验实际请求顺序和次数、连接池复用、服务器已执行但断开响应、后续操作不被锁住，不依赖真实账户。测试只使用本机虚构的 New API HTTP 服务；不安装、导入或启动 Cockpit 服务，不请求真实站点或模型。

需要检查真正的扩展宿主时，在已安装 VS Code 的桌面环境运行：

```sh
npm run test:host
```

可用 `VSCODE_EXECUTABLE_PATH` 指定 VS Code 可执行文件。该检查创建独立的临时用户目录和扩展目录，不读取个人 VS Code 配置、PAT 或其他扩展。

宿主检查通过临时测试入口取得真实 `ExtensionContext`，使用实际的 `globalStorageUri`（包括桌面版的 `vscode-userdata`）与原生配置选择器，走完整的 Claude 配置定位、草稿及手动保存流程；修改范围校验在独立测试用户目录内，不读取个人配置或凭据。

草稿检查使用虚构 KEY 和临时配置文件：覆盖开启延时/失焦自动保存时原文件不变、编辑草稿后手动覆盖、仅手动保存才创建新目录/文件、原配置被并发修改时停止覆盖及重复草稿保护；不改个人 Claude / Codex 配置。纯文本检查覆盖 JSONC 注释、TOML 的引号键/点分键/内联表/子表/多行字符串、重复生成不追加、认证模式替换及无关设置保留。

若需验证某个站点在真实扩展宿主中的连续 HTTPS 请求，可显式指定测试站点：

```sh
COCKPIT_DIAGNOSTIC_ORIGIN=https://gateway.example.com npm run test:host
```

此项使用固定的无效凭据，要求六次查询及修改路径请求都返回 HTTP 401，不读取真实 PAT，也不授权任何 KEY 修改。它只验证网络通道，不能证明账户权限或实际 KEY 修改成功。默认检查不访问外部站点。
