# 变更记录

## 0.4.2

- 余额直接调用 New API 的 `/api/user/self`，不需要安装 Cockpit 或开启账户 MCP；旧站点连接地址自动兼容，不再发送 MCP 请求。
- 首次连接读取 `/api/status` 的额度单位，此后缓存一小时；普通刷新只读一次本人账户。整数额度精确换算，不猜测单位、不以零替代错误。
- 保留默认 15 分钟更新、余额手动最短 60 秒、跨窗口/重启的刷新与 429 等待；升级不会绕过已有等待。
- 保留新建丢失回执、跨页修改和删除的插件内结果核对，不重复写入、不跳转网页、不增加二次确认。
- KEY 改组沿用官方 PUT，保留最新查询中的其他配置；不依赖 New API 补丁。KEY 查询和修改前后查询仍不设插件间隔。
- Claude/Codex 未保存草稿、连接密钥库和 KEY 缓存规则不变。随 Cockpit v0.4.1 镜像提供下载，也可独立安装使用。

## 0.4.0

- 随 Cockpit v0.4.0 正式发布，网站“文档 → 辅助工具”可下载安装包；GitHub Release 提供从同一发布镜像导出的 VSIX 和 SHA-256 清单。
- 构建前清理生成目录，避免已删除模块残留在安装包；导出系统下载目录时清除旧版本的生成包，不影响账户连接、KEY 缓存或配置草稿流程。
- 余额、KEY 管理、Claude / Codex 草稿与本机用户配置路径修复均保留；KEY 操作及结果确认仍在插件内完成。

## 0.3.1

- 修复 Claude 配置入口误报“无法确定本机 VS Code 用户配置位置”：支持 VS Code 正常使用的 `vscode-userdata` 本地用户数据 URI，转换为对应磁盘路径，不再错误拒绝。
- 宿主检查直接使用真实激活上下文与原生配置文件选择器，验证 Claude 配置从定位文件、打开未保存草稿到手动保存的流程，不再只使用手工构造的文件路径。

## 0.3.0

- KEY 旁增加“配置 Claude / Codex”入口；选择模型 KEY 和客户端后打开可编辑的未保存草稿，不直接修改原配置。
- 草稿内 Ctrl+S / macOS ⌘S、编辑器保存按钮和顶部保存入口写入对应目标文件；自动保存不触发覆盖，其他文件保存不受影响。
- Claude Code 覆盖用户设置中的地址、Bearer KEY 和冲突认证/路由开关；Codex 生成同目录 config.toml + auth.json，识别 CODEX_HOME，同名 Provider 覆盖而不追加，不混用旧 OAuth。
- 保留无关设置、模型选择、MCP 和注释；已有未保存修改、重复草稿、格式错误及原文件中途变更时停止覆盖。手动保存才创建目录并原子替换文件，含 KEY 配置在 macOS/Linux 限为 0600。
- 复用完整 KEY 的显式读取缓存，不自动查询模型或发送模型请求；补充真实 VS Code 编辑、自动保存和手动覆盖检查。

## 0.2.3

- 网络请求改用 VS Code 扩展宿主的内置 `fetch` 与连接池，修复连续“查询 → 修改 → 查询”时 HTTPS 连接被重置、修改请求未到达服务器的问题；不再依赖会被宿主代理补丁替换的自定义 HTTPS Agent。
- 网络错误按实际错误码区分断线、DNS、超时和证书校验失败，不再把所有连接失败统称为证书问题；错误不展示服务端正文或凭据。
- 保留 KEY 手动查询无间隔、修改前后各查询一次、不重复发送写请求及插件内自动确认；HTTPS 校验、禁止重定向、超时和响应大小限制不变。
- 补充真实 VS Code 宿主连续 HTTPS 通道检查；使用无效凭据，不操作真实账户 KEY。

## 0.2.2

- 移除“核对修改结果”、网页核对提示及全局待核对锁；操作和结果确认都在插件内完成，不再因一次回执异常阻止之后的修改。
- 删除、改组回执丢失时，自动使用操作后查询确认是否生效；已生效就显示成功，没有变化则显示错误，不自动重复写入。
- 改分组选择后直接执行，不再要求二次确认或填写“已经暂停”；删除保留一次正常确认。
- 按 KEY ID 使用操作前的新数据，不因缓存中的名称、分组变化反复要求用户重新核对；已删除的 KEY 无需再发送重复 DELETE。
- HTTP 完成状态改由响应自身判断，不将请求的 close 事件提前当成响应失败；保留查询前后各一次、缓存与无查询间隔规则。

## 0.2.1

- KEY 管理改为手动查询，无插件查询/写入时间间隔；不受余额冷却或上次 KEY 429 的本地等待记录影响，不自动重试。
- 新建、删除、改分组均在操作前后各查询一次；操作前查询失败不修改，写入失败或结果未确认也不重复发送写请求。
- 改分组复用操作前查询返回的最新配置，不再重复读取同一 KEY；已确认的分组和完整密钥继续按需缓存。
- 保留正在执行请求的合并与重复写入保护、账户隔离和未知写入结果的人工核对；余额刷新规则不变。

## 0.2.0

- 账户余额下增加独立 KEY 管理分区，使用原生分隔条；按需加载本人 KEY，按实际分组显示。
- 支持申请、删除、复制 KEY 和切换分组；使用用户 PAT 的对应 `api_key:*` 权限，不借用管理员身份。
- 列表、分组及已显式复制的完整密钥仅在当前连接内存缓存，不按时间失效；再次查看或复制不重复查询。手动刷新更新列表并清空旧缓存，新建、删除、改分组成功后强制刷新列表一次。
- 不自动读取完整密钥；未缓存密钥的显式读取限频，删除和写操作需确认，结果未确认时停止继续写，不自动重试。
- KEY 不随余额定时刷新，429 等待与余额共享；保留原有连接、状态栏和余额刷新间隔。

## 0.1.1

- VS Code 底部状态栏同时显示账户名与可用余额，例如 `demo-user · 可用余额 123.45`；点击查看账户侧栏。
- 查询失败时标为“上次余额”，保留更新时间；刷新间隔、跨窗口冷却和 429 等待规则不变，不增加请求。

## 0.1.0

- 状态栏和账户侧栏查询本人余额、累计消费及累计请求数。
- 独立插件直接请求现有 Cockpit 账户入口，无须另装 MCP 客户端；使用用户 API PAT，仅需 `profile:read`。
- 地址和 PAT 使用 VS Code 密钥库保存，不保存账户余额、不使用模型密钥、不调用模型。
- 默认 15 分钟刷新，手动至少间隔 60 秒，合并并发请求；多窗口及重启共享站点冷却。
- 429 按 `Retry-After` 暂停，至少等待 15 分钟；不立即重试，失效认证停止自动查询。
