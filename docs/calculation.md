# 统计口径

## 展示、区间与聚合

- 页面表格中的金额和单价统一显示两位小数，包括统计明细与合计、月度归档、历史费用对比、用户/KEY 余额及配额预览。仅格式化显示；计算、API、Excel 导出和金额悬浮详情保留原精度。表格各行显示值相加可能与按原值汇总后显示的合计存在分位尾差。

- 页头站点名称和浏览器标题读取 New API 数据库 `options.SystemName`，页面刷新时重新读取；未配置时显示 New API。

- 北京时间精确到秒，结束时间包含该秒；SQL 使用半开区间，单次最多 367 天。
  API 参数也支持纯日期格式，结束日期包含全天。
- 快捷按钮点选后立即查询：上个月为完整自然月（00:00:00 至 23:59:59），本月为当月1日 00:00:00 至当前时刻；
  近30天、近7天、近1天按当前时刻往前推。浏览器处于其他时区时仍按北京时间填写。
- 仅统计 `type=2` 消费日志，按用户 ID、用户名、模型聚合。
- 当前模型口径约定如下，部署前必须确认与上游日志一致，不依赖历史日志的 `usage_semantic`：
  名称以 claude 开头的模型输入不含缓存，直接作为纯输入；其余所有模型纯输入 = max(原输入 - 缓存读 - 缓存写, 0)，逐请求计算后汇总。
  原始去重总量：Claude 为原输入+输出+缓存读+缓存写；其他模型为原输入+输出，不重复增加缓存。
  此为应用当前的模型口径约定，不代表所有 OpenAI 兼容协议必然使用相同上游语义；若渠道或模型命名改变须重新确认。
  OpenAI 缓存读写前缀可能重叠，不能以四项之和替代原始去重总量。
- 缓存写优先 `cache_write_tokens`，其次 `cache_creation_tokens`；不重复叠加。
- 页面和 Excel 的输入列均为纯输入（不含缓存读写），输出列使用 completion_tokens，缓存读写单列。
  API 的 raw_input_tokens 保留未扣除缓存的日志输入。
- 区间平均 TPM = 去重总 Token × 60 / 区间秒数；区间平均 RPM = 消费日志条数 × 60 / 区间秒数。
  分母为完整所选区间（包含结束秒和空闲时间），不是实时值或峰值；RPM 仅统计 type=2 消费日志，不包含错误等其他日志。
  切换用户后使用同一区间重新计算该用户的均值。
- 排序标签页包括模型消费、用户 Token 用量、用户消费，展示全部排名；用户 Token 排序按上述去重总量。
- 金额来自实际 `SUM(quota)/500000`，不按当前价格重新计费。
- 每条消费请求从日志 `other` 还原请求发生时的价格：倍率计费使用日志中的模型、输出、缓存和缓存写入倍率；表达式计费仅安全解析日志保存的 `expr_b64` 与 `matched_tier`。按次计费或无法完整解析的请求没有可确认的 Token 单价，不借用当前配置。
- 同用户、模型（分令牌时还包括令牌）的历史价格相同才合并；不同价格分行。历史价格能唯一匹配当前模型某档价格的，请求并入该档，显示当前档位名和价格；匹配不到的显示 `-`，不同历史价格仍分行。没有写入用量时，历史日志未提供缓存写单价不妨碍匹配；其他已使用类别必须匹配。
- 倍率不作为分行条件。按每个日志价格／分组／倍率桶比较当时倍率与该分组当前 `GroupRatio`；仅发生变化且历史价格能匹配当前档位、价格完整并有非负唯一解时，以当前价格和当前分组倍率反算缓存读取 Token。每桶四舍五入为整数，然后汇总行内缓存读取量和总 Token；金额始终取日志，不改数据库。未匹配当前价格、缺价或无效解的桶保留原始 Token。
- 页面、排名、TPM 和 Excel 使用上述合并口径；API 的 original_cache_read_tokens / original_total_tokens 保留原始值供核对。倍率列取该行最后请求所属分组的当前倍率；悬浮公式对不同倍率分别列出，不能把不同倍率套一个乘数。
- 消费金额支持悬停、键盘聚焦或点击查看价格、Token、倍率、试算与日志实际金额。逐请求配额取整、缓存 Token 取整及其他计费项目可能产生差额；缺少非零用量的单价时不强行给出试算。
- 倍率计费的当前输入价格为 `ModelRatio * 2` 元/M，其余三类乘对应 options 倍率。
  若模型的 `billing_setting.billing_mode` 为 `tiered_expr`，优先读取 `billing_setting.billing_expr`，
  仅安全拆分 `tier("档位", p/cr/cc/cc1h/c × 数字的加法)` 及按 `len` 分两档的表达式。
  `p`、`c`、`cr`、`cc` 分别对应输入、输出、缓存读、缓存写价格；
  页面和试算统一把全部缓存写入量按第一档（5 分钟）价格处理，不展示 1 小时价格。
  当前价格仅用于档位匹配和倍率变化时的缓存配平，不覆盖请求的历史价格。
  复杂或缺失表达式不猜测价格；页面与 Excel 的消费金额仍取日志。
  Excel 的「表达式价格」工作表展示当前档位价格，便于核对匹配结果。
- 零消费且没有请求的用户没有模型明细；实际存在的零金额请求保留。
- 页面用户筛选作用于当前快照；Excel 导出重新查询所选区间和用户，活跃区间可能变化。
- 用户模型明细最后一列固定提供“查看日志”，以当前协议、域名和端口在新标签页打开 New API `/usage-logs/common`，按该行用户名、模型和当前已成功查询的统计起止时间筛选全部日志（含消费、失败等类型）。时间按北京时间转换，并包含结束秒，不受浏览器时区或尚未提交的时间输入影响。不额外限定账本、档位、令牌或分组；模型汇总模式不限定模型，仍沿用相同统计周期。此入口仅网页展示，不进入 Excel，也不改变统计金额。
- Excel 基础工作表为用户模型用量、模型消费、用户Token用量、用户消费、区间汇总；有表达式模型时另加「表达式价格」。
  用户模型用量表按历史价格／匹配档位拆行，价格单元格保持数值属性；各工作表均遵循当前时间和用户筛选。
- 明细表“显示列”提供缓存命中率、每百万 Token 金额和失败请求，默认均不勾选，用户选择保存在当前浏览器。
  命中率为缓存读 /（纯输入 + 缓存读），每百万 Token 金额为实际金额 / 总 Token × 1,000,000。
  合计按汇总量计算，不平均各行比率；分母为零或用量无法确认时显示 `—`。
- 勾选“失败请求”才查询 New API `logs.type=5`，按 `other.status_code` 汇总，使用与消费数据相同的账本、时间、用户、模型、令牌和分组范围；
  只发生失败而没有消费日志的维度也会在明细表显示，但不加入消费指标和排行榜。错误码可显示多行，例如 `429 3次`、`502 1次`。
  切换该列会按当前已展示区间重新查询，保留仍有效的明细筛选；未提交的时间输入不生效。
  三列均仅在浏览器展示，Excel 始终不包含，导出也不查询失败日志。
## 异常日志与展示详情

正常日志使用数据库聚合。消费日志的 `other` 损坏或关键数值无法解析时，
不会丢弃日志金额，也不让整张报表失败：仍保留 `quota` 对应的费用和消费请求数；
无法确认的缓存读写、纯输入或总量显示为 `—`，API 为 `null`，不借用当前价格编造试算。
非 Claude 的原输入+输出仍可确认总量；Claude 缺失缓存信息时总量不可确认。
包含未知类别的合计/Token 排名也不把它当作零；Excel 留空对应未知数量的合计，金额合计照常保留。
损坏失败日志仍计入失败次数，无法解析的错误码显示“未知”。

配置监控库后，网页请求采用精简列表并在悬浮时读取查询瞬间冻结的计算公式。
详情有 15 分钟有效期及最近 10 份/管理员的保留上限；失效需重新查询，不使用新的日志或价格
拼接旧报表。未配置监控库或未请求精简响应时，直接返回完整数据。
所有外部 Excel 字符串均作为文本，模型名、档位或显示名以 `=` 开头也不作为公式执行。
