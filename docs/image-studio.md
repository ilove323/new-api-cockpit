# 生图工作站

在 `/cockpit/image-studio` 选择自己的 KEY 和该 KEY 可用的图片模型，然后新建图片或编辑主图。所有已启用的登录用户都能使用，管理页权限不变。

## 怎么用

- **新建图片**：写下画面描述，选择输出参数，生成一张候选图。
- **编辑主图**：导入、拖入或粘贴 PNG、JPEG、WebP；写修改要求，或直接在图上加文字、箭头、圈线。
- **只改一部分**：用选区笔刷、矩形或圈选划定区域，再写要求或加指导标注。提交按钮会显示「生成局部修改」。
- **编辑标注**：用「选择」移动标注，拖动八个控制点调整大小；Shift 拖动时，矩形和椭圆约束为等宽高，笔迹按原比例缩放；文字始终等比缩放。选「文字」后，在画布上点击要写字的位置直接输入，不需要右侧输入框；双击已有文字修改。点击别处或 Ctrl / Command + Enter 完成，Esc 取消本次文字修改；Enter 换行。文字输入与提交的指导图使用同一位置、颜色、字体和字号。「擦除标注」只擦指导笔迹，不擦主图和修改选区。删除、擦除、缩放都可以撤销。
- **比较再应用**：点击候选缩略图或「预览」打开大图。滚轮或双指缩放，放大后拖动，双击放大/还原；「适应」回到完整画面。箭头按钮切换候选，也可勾选与提交时的主图对比。点关闭、遮罩或按 Esc 返回画布，满意后再应用为主图。下载、预览、丢弃都不会替换主图。

选区和指导标注是两回事：**选区规定修改范围，标注说明修改内容**。隐藏它们只是方便观察，不会删除提交内容。

| 当前输入 | 提交操作 |
|---|---|
| 文字，没有主图 | 文生图 |
| 主图 + 文字，没有选区 | 整图编辑 |
| 主图 + 标注，没有选区、没有提示词 | 按标注整图编辑 |
| 主图 + 选区 + 文字 | 局部修改 |
| 主图 + 选区 + 标注，没有提示词 | 局部修改 |
| 只有主图和选区，没有文字或标注 | 先补充修改要求 |

有标注时无需再抄一遍提示词。服务端添加固定的图像角色说明，不额外调用文字模型，也不做 OCR。
参考图可以指定人物/物体、风格、构图或普通参考用途；这只是给模型的说明，不是供应商专用控制参数。

## 提示词和画布文字怎样发给模型

**提示词**就是下方输入框里的生成或修改要求，不是附带说明。**画布文字**则和箭头、圈线一样，是带位置的改图标注。两者一起告诉模型要做什么，但传输方式不同：

| 内容 | 模型收到的形式 |
|---|---|
| 下方输入框的提示词 | 文本 `prompt`。文生图直接使用；改图时先添加主图、指导图、选区和参考图的固定说明，再接上「用户提示词」和输入内容 |
| 画布上的文字、箭头和圈线 | 在主图副本上按画布位置绘制，导出为一张 PNG 指导图；不发送文字对象、坐标 JSON，也不把标注识别成文本再拼进提示词 |
| 主图 | 干净的工作主图，不把标注直接画到原图上 |
| 修改选区 | 支持原生遮罩的渠道收到单独的 alpha 遮罩；其他渠道收到指导图里的青色选区，详见下节 |

例如，在天空上写「这里换成晚霞」，下方写「保留建筑，整体偏暖色」，改图请求会发送：

1. 第一张：没有标注的主图。
2. 第二张：在天空位置写着「这里换成晚霞」的指导图。
3. `prompt`：固定的图片说明，以及「用户提示词：保留建筑，整体偏暖色」。

固定说明要求模型按指导图理解文字、圈线和箭头，**不要把指导标记画进最终图片**。所以图上的「这里换成晚霞」应当作为指令，而不是成图中的文字。标注不会在本地直接贴到生成结果上；所见即所得指的是标注编辑，不是确定性的成图排版。

如果想在成图里保留标题，请在提示词中明确写出，例如「在指定位置添加标题『春日上新』，文字必须出现在成图中」，画布标注用于指示位置。文字仍由生图模型生成，不保证逐字或像素级一致。

当前没有给提示词和标注设置冲突优先级；互相矛盾时由模型解释，不保证哪一方生效。应将标注用于定位和局部要求，提示词用于整体要求，避免一处写红色、另一处写蓝色。只有标注时可以不填提示词，但只有选区不能提交。

KEY 必须属于当前账号，不限制分组名称；`auto`、默认组、自定义分组均按 New API 的实际授权处理。管理员也不能代用别人的 KEY。浏览器只发送令牌 ID，原始 KEY 仅由后台通过 New API 的本人 KEY 接口读取；不补建 PAT、不创建 KEY、不改组。
选中 KEY 后查询其模型目录，再与当前路由及已配置图片协议求交；不依赖模型名称前缀。支持其他名称或别名，但需要配置相应的 Images 协议，不会把文本模型当作图片模型。模型由用户选择，不固定默认型号。参数随当前操作和渠道契约变化。

改图选择「自动」时，只从渠道已声明的输出尺寸里选最接近原图比例的档位，不把原图尺寸取整后当成新的输出尺寸。例如，渠道支持三种 1K 档位时，837×1280 的竖图使用 1024×1536 工作画幅。主图、选区和标注一起等比映射，合成后的原图仍是 837×1280。自定义尺寸只有在渠道明确支持时才提供，且需用户主动选择。

## 局部修改怎样保留原图

工作站支持两条事先确定的路径：

| 渠道契约 | 发给模型的内容 |
|---|---|
| `native-mask` | 干净主图、alpha 遮罩；有标注时追加指导图 |
| `reference-only` | 干净主图、带青色选区与指导标注的参考图；不发送 `mask` |

主图、遮罩、指导图使用同一坐标映射，指导图排在主图之后，其他参考图再跟随。主图本身不带圈线或选区着色。
不支持 mask 的渠道直接使用第二条路径，不会先收费试错再去掉 mask 重发。

两条路径都按**提交时的选区**将结果合成回原图。羽化仅向选区内部衰减，选区外保持原图解码后的 RGBA；局部合成导出 PNG。模型原始结果也保留供比较和下载。
模型返回的尺寸不对应时，不强行拉伸合成，只提供完整模型结果；用户可以明确将它作为新的整图使用。

候选始终绑定提交快照。等待期间换图或修改画布，不会改变已提交的素材，也不会被迟到结果自动覆盖。
最多保留 4 个候选和 4 个主图版本，清理时释放相关图片资源。图片、提示词和画布只在当前页面，刷新后不恢复。

## 等待、错误与重复提交

每次明确提交生成一张图（`n=1`）。同一用户最多一笔、全站默认两笔，忙时返回 `429`，不排队。Cockpit 不自动重试，也不会在认证刷新后重放付费 POST。

请求状态为「准备输入 → 等待结果 → 候选就绪 / 明确失败 / 结果未知」。结束等待只结束浏览器等待，不代表 New API 已取消请求或退费。结果未知时先看 New API 日志，再手动开始新请求。
错误会区分权限、额度、参数、内容审核、限流和连接异常；技术详情里保留可用的安全错误码、参数名与请求 ID，不展示供应商原始报文。

Redis 中只保存短期回执：账号 ID、输入摘要、派发/结束状态及时间。默认有效期 24 小时，不保存图片、提示词、KEY 或生成结果。
有效期内，同账号重复使用一个请求 ID 不会再次派发；同 ID 换输入返回 `409`。它不是后台任务，也不提供按 ID 找回图片的接口。回执到期、丢失或恢复旧备份后不能保证去重。

New API 自己的上游重试由它的配置决定，不能把 Cockpit 的一次 POST 等同于供应商只尝试一次。工作站不会为绕过内容审核自动改写请求。

## 资源上限

| 项目 | 上限 |
|---|---|
| 总上传，含表单和遮罩 | 24 MiB |
| 单张输入图 | 8 MiB |
| 主图 / 全部输入像素 | 16 MP / 32 MP |
| 图片数量 | 最多 4 张，主图和指导图也占名额；渠道可更少 |
| 原生遮罩 | 带 alpha 的 PNG，小于 4 MB，与工作图同尺寸 |
| 上游 JSON / 单张结果 | 48 MiB / 8.5 MP |
| 连接 / 上传 / 请求总截止 | 10 / 30 / 300 秒 |

输入按实际内容解码并统一 EXIF 方向，不接受动画、SVG、HTML 或远程 URL。输出优先 Base64；URL-only 渠道必须由管理员显式配置精确 HTTPS 主机或公网 CIDR 白名单，任何方式都不允许访问私网地址。服务端验证后下载并正规化，浏览器仍只收到图片数据。

## 部署与接口

- 配置显式、版本化的渠道契约。没有配置的渠道不会因为类型是 OpenAI 就自动获得完整编辑能力。
- 同一模型所有可能路由取共同契约；生成和编辑分开声明参数。提交时再次校验 KEY、模型授权和契约修订，变化则在调用模型前返回 `409`。
- 图片池需要监控库的并发锁及可靠的 Redis 回执存储。任一不可用时拒绝新付费请求，不降级为浏览器锁。
- 不新增工作站数据库表，不修改迁移历史、现有用户、PAT、KEY 或额度。

具体配置见[部署](existing-installation.md#生图工作站请求池)，请求字段见 [API](api.md#生图工作站接口)。

画板与预览直接使用 GPT Image Playground 源码，指导图合成移植自 InvokeAI；固定提交、许可证和维护方式见[源码说明](image-studio-sources.md)。New API 登录、本人 KEY、模型权限和请求派发仍沿用 Cockpit。
