# AI 助手 v2 前端实现

本文描述当前前端行为。测试使用本地 Flask、离线事件和合成模型，不发起付费调用；开发入口见[贡献指南](../../../CONTRIBUTING.md#ai-助手离线回归)。协议、运行、存储和权限的硬限制由后端实现，不能由页面开关放宽。

## 默认设置与兼容

### 文件上传

- 配置读入后，空页面的文件选择器可用。选中合法文件后仅新建一个聊天并上传；不要求先选 KEY/模型，不调用模型，不自动切换全局模式。先在浏览器检查类型/尺寸，超限不会先创建空聊天。
- 单文件上限为 50 MiB（52,428,800 字节，含边界；界面显示 50 MB），不再显示难读的原始字节上限。仍仅接受原允许列表的 UTF-8 文本，不新增 PDF/Office/图片解析。
- 自动新建期间禁止重复选择；创建失败/结果不明不自动重试。新建过程中切到其他聊天或退出账号，迟到结果不能把文件上传到新身份/另一聊天。有活动操作、损坏存储、登录失效或配置未读入时仍禁用，并给出简短原因。 服务端同一实例只接纳 1 个 HTTP 上传，其他上传忙碌时返回 429，页面明确要求手动重试，不自动排队或重复上传。 文件上传客户端等待延长至 210 秒（其他普通 API 保持 30 秒），避免大文件仍按旧小请求时限被取消。
- HTTP multipart 文件体、解析缓冲、存储归一化、公共配置和聊天 Nginx 示例均同步调整；个人设置/Skill、JSON请求、工具返回、输出文件和模型上下文的限制不随上传上限放大。大文本按有界行页读取，避免将数千万行一次展开成内存列表。

### 全局 KEY / 模型 / 模式与浏览器缓存

- 选择栏位于聊天布局上方，不属于任何会话卡片。新建、切换、删除聊天或返回空页面均保留当前选择和内存模型目录；聊天 `last_selection` 仅作为历史记录，不再反向覆盖全局表单。
- 当前账号使用同源 `localStorage` 键 `cockpit.chat.selection.v1.u<user_id>`，严格只接受 `{v:1,token_id,model,mode}`。数字 KEY ID 不是 KEY 密文；不保存名字/掩码、能力 revision、模型目录、消息/草稿、Skills、Memory 或凭据。不是 Cookie，不随业务请求自动发送，也不跨浏览器/设备同步。
- 刷新或重新登录同一账号时先读取本人可用 KEY，再以非计费 `/models` 请求校验当前模型与能力 revision；缓存不充当授权凭据。失效 KEY 清空引用但不自动换其他 KEY；缺失模型不自动换模型。界面没有模式选择，旧模式偏好被完整助手默认值替代；不因未声明工具而禁用聊天模型，不在恢复选择时生成回答。被阻止或损坏的存储不阻断页面，至少保留当前页面内存选择。
- 退出或账号变化清空页面 KEY/目录和旧响应，保留原账号独立的选择缓存供本人下次登录，不让其他账号继承。目录读取使用账号级 Scope，并按 KEY/请求版本核对；聊天切换可以保留该读取，旧 KEY/旧身份的迟到成功或失败不能覆盖新选择。
- 缓存恢复只查询本人 KEY/模型目录，不发送聊天、不中断已冻结的历史运行、不生成回答或自动重发。普通的聊天切换和只读恢复继续复用目录；页面刷新存在缓存时允许额外一次非计费目录请求，不再把“所有刷新请求必须全是 GET”当成该场景约束。

- 页面删除候选回答数、上下文策略、联网和自动 Memory 四个控件，不以隐藏输入代替。固定 `candidate_count:1`、`context_strategy:"adaptive"`，默认 `auto_memory:true`。
- 不再提供普通聊天/Agent 模式控件，控制器默认使用内部兼容值 `mode:"files"`，并按站点可用性默认启用联网。引用附件由服务器直接读取正文，文件和联网工具按需执行，不以工具声明限制模型选择，不在打开页面时自动访问公网。
- 默认值由控制器直接生成，不依赖旧控件是否存在/勾选，不在切换聊天或刷新后复位成关闭。站点明确禁用自动 Memory/联网或无可用联网工具时遵守限制；没有搜索后端不等于抓取/下载不可用。
- 上下文不能选择或静默退到 `recent`；服务端明确未提供自适应时禁用发送并提示。完整历史保留不等于完整历史全部进入模型输入。
- 页面发送始终显式附带四个顶层参数。API 默认值、参数范围和旧多候选历史兼容不变；直接调用 `buildRunRequest` 省略 `options` 仍保持原 DTO 全部字段及键集合不变。公共配置继续支持 `schema_version:1`，缺省 `features` 或旧模型目录不抛空引用错误。

## 模型操作区域

模型区域仅保留 KEY、载入模型目录、模型和模式的操作项。默认状态文字、“能力与计费说明”折叠区、模型目录提示和“管理我的 KEY”链接全部从模板移除，相应控制器文案/DOM 依赖与样式也删除，不是隐藏后保留。相邻的完整历史说明段落同时清理。真实无可用模型或不支持自适应等故障仍通过状态区提示，不能让禁用发送变成无原因失败。

上述清理不改变运行行为及计费边界：

- 三协议的当前页面均只生成一个回答，对应一次主回答请求，不再按候选数派发多个回答。
- 文件 Agent 的单分支仍可多步调用。主请求与摘要、原生压缩、记忆提取等辅助请求有独立上限，公共配置与服务端硬限制保持不变。
- 自适应摘要 / 压缩可能产生额外计费请求；默认开启的自动记忆可能额外计费并修改个人 `MEMORY.md`，但无合格事实不会写入。二者明确区分。
- `features.web` 和工具返回仍区分网页抓取、链接下载与搜索。搜索未配置或配置无效不会关闭仍可用的抓取/下载；文件与联网模式默认可用的工具仍受服务端硬限制。不再在模型操作区常驻这些说明。

实际运行按 `run.dispatching.request_index` 去重统计真实请求，并以 `purpose` 区分 `main`、`summary`、`native_compact`、`memory`。`run.usage` 同一请求重复快照只计一次，按用途分别显示次数与 Token。未报告用量显示未知，部分报告标记部分；不会把未知当作零费用，也不会把原生多候选乘算成多次请求。

## 历史多候选分支兼容

当前页面不创建新的多候选回答；以下只处理已有历史或其他兼容 API 客户端生成的记录。

- `candidate_index` 按 0 开始接收、按 1 开始显示。每条助手消息独立保存正文、公开推理与完成状态；派发事件的 `candidate_message_ids` 可补足消息事件缺省的候选索引。
- 仅最新已完成、尚无后续运行的多候选轮次可选择。运行中、不完整或含工具调用的候选不能作为完成分支选择；有后续运行后，旧选择只读。
- 最新完成的多候选尚未选择时，发送按钮和直接提交处理器都拒绝发送。
- 点击选择仅提交一次 `POST /conversations/<cid>/runs/<rid>/candidate`，正文为 `{expected_revision, candidate_index}`。响应后只读恢复聊天元信息、全部已提交历史的分页高水位、运行状态与文件；既有历史不裁剪。
- `candidate.selected` 可跟在终态之后，更新分支而不重新打开运行。后续上下文只采用所选分支由服务端保证；前端不拼接或混合其他候选正文。
- 网络不确定或版本冲突不自动重复写入，发送保持关闭直到只读核对完成。选择期间也禁止重复选择和发送。

## 公开推理与安全渲染

`assistant.reasoning` 的 `raw` 和 `summary` 分别标记为“公开推理文本”和“公开推理摘要”，同时显示来源字段 `reasoning_content` / `reasoning` / `thinking`。默认折叠，可展开查看；明确说明这只是接口公开输出，不声称获取隐藏思考原文。

正文最终快照替换已累积的正文增量，但不抹掉公开推理；省略或空白的补充快照不抹掉已有正文。重新投影和只读恢复后仍保留内容与展开状态。

正文采用原有非 HTML Markdown 渲染；推理、审计、工具和通知使用文本节点。不解析原始 HTML，不创建远程图片，不展示 `assistant.protocol.state`。协议 opaque state 仅随历史保存，不成为 UI 内容。

## 压缩检查点只读元信息

- `context.compacted` 表示本轮新生成检查点；相关辅助请求由真实派发事件独立计数。
- `context.selected` 表示复用已有有效检查点，明确提示“此次复用没有新增辅助模型调用”；该事件自身不增加请求计数。
- 二者显示 `summary` / `native` 模式、覆盖轮数、来源 SHA256 与检查点 SHA256。忽略检查点文件路径，不读取或展示检查点 opaque 内容；没有引入 read-window 接口。
- `run.accepted.context_from_run_ids` 仍作为服务端采用的覆盖/近期轮次记录，不被前端误解释为只包含最近几个可见聊天轮次。

## 本人 Memory 审计与撤销

`memory.proposed` 只显示更新意向已追踪，明确不是写入确认，不展示其中的意向正文，也不自动执行写入或撤销。

`memory.updated.data.audit` 按已确认契约接收。仅当审计版本、类型、个人文档名和版本信息有效，且 `owner_user_id` 与服务端模板注入的当前用户 ID 匹配时，才展示可折叠的变更前后正文、SHA256、个人上下文/MEMORY 版本及来源消息/事实数量。身份缺失、归属不一致时只留通用通知，不展示内容或撤销按钮。该前端检查不替代服务端本人授权。

撤销流程：

1. 仅本人显式点击“撤销本次自动记忆更新”才启动；内容未变化、运行未终止或已撤销的记录不可撤销。
2. 只读获取当前个人上下文，校验当前 MEMORY 的修订和 SHA256 仍与该次更新后的版本一致；后续修改拒绝覆盖。
3. 再只读获取最新聊天版本，确认无活动运行且存储可写。
4. 仅提交一次 `POST /conversations/<cid>/runs/<rid>/memory/undo`，正文 `{context_revision: 最新个人上下文版本, expected_revision: 最新聊天版本}`，不使用冻结的历史上下文版本。
5. 接收 `{context, conversation}` 后重新 GET 个人上下文及历史；保留当前聊天已载入的 Skills，不因 Memory 撤销而清空。冲突或丢失响应也仅只读核对，不自动重发撤销。

`memory.reverted` 可跟在运行终态之后，标记已撤销并关闭撤销按钮，不更改助手正文或重启运行。只读恢复发现自动更新/撤销后的个人上下文版本较新时，会再 GET 最新个人设置，避免下一轮沿用旧版本。撤销不触发模型调用。账号/聊天切换会清理审计正文、待处理操作和旧响应。

## 历史与身份边界

保留原有聊天列表及事件分页、高水位完整性校验、只读恢复、停止前先提交取消、文件 Blob 下载和账号切换清理。候选、Memory 请求继续使用同一 `Scope`、登录 Cookie、写请求标记和不可自动重放策略。旧账号或旧聊天的迟到响应不能恢复正文、个人设置或发送可用状态。浏览器不持久化聊天正文、推理、审计或未发送草稿。

## 输入框附件与输出列表

附件上传入口位于发送按钮旁，使用隐藏的原生多文件选择器，也接受输入区拖放。逐文件上传前先检查整批类型、大小和总引用数；不调用模型。每个成功响应核对原请求的文件 ID 和上传类型，才加入本轮引用；部分失败保留已成功项，停止其余上传，不自动重传。

输入框卡片表示待发送的 `attachment_ids`，× 仅取消引用。接受事件确认后清空本轮卡片，并在实际用户消息内按文件 ID 关联不可变附件；下载与再次引用都是显式操作。尚未被消息引用且不在输入框中的上传文件另列于聊天区，避免刷新或移除卡片后找不到文件，不伪造成已发送消息。

输出区仅渲染 `kind=output`，最近生成的在前，各版本分别下载。下载沿用受保护的 Blob API，不信任 `download_path` 外链。所有文件按钮捕获所属聊天的 Scope ticket，切换聊天或账号后旧事件/下载响应不能带回旧文件。50 MiB 上传、单文件写入限制、服务器读取正文和跨用户/聊天隔离保持不变。桌面及 390px 浏览器夹具覆盖多选、移除/再引用、发送确认、刷新、点击下载和长文件名布局；夹具不调用真实模型。

## 聊天页精简与持续载入兼容

主界面移除 Skills 按钮及专用窗口、手动“只读刷新状态”按钮，以及逐轮“查看上下文”按钮和固定默认能力说明。不以隐藏、折叠或新菜单替代这些入口。保留个人设置链接、实际运行状态、模型、用量、错误与有效的历史操作。打开聊天、流结束或断线后仍自动只读恢复；历史接口和快照存储不删除。

服务器 `conversation.loaded_skill_ids` 是恢复来源，最多 3 个有序唯一 ID。写入使用原聊天 PATCH 的互斥请求 `{expected_revision,context_revision,loaded_skill_ids}`，不收费、不改库或历史快照。发送仍使用兼容的 `skill_ids`，但由已确认的持久载入状态填写；旧历史不从曾用过的快照隐式载入。

缺少已移除的控件节点不影响个人上下文读取、会话载入状态恢复或发送。历史未达到已提交高水位时禁止发送；迟到请求由 Scope 丢弃，较早个人设置请求不能覆盖新版本。库删除后的引用仍校验，不能静默剔除并收费生成。原模板管理接口及可选控件适配保持兼容，不再由聊天页提供入口；账号切换清除旧内容。

持续载入和竞态回归见 `tests/test_chat_loaded_skills.cjs`；可选真实浏览器入口见[贡献指南](../../../CONTRIBUTING.md#ai-助手离线回归)。

附件格式由 `/chat/config` 的允许列表驱动，不在浏览器假定“只支持文本”。PDF、Word、Excel、图片与文本共用输入框卡片、移除、历史再次引用和鉴权下载流程；解析与视觉内容由服务器完成，浏览器不把二进制解码成文本或自动上传到第三方。视觉能力不作为禁用整个模型下拉选项的理由。
