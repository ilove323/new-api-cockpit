# 性能机制

模块和数据流见[架构说明](architecture.md)，金额与 Token 规则见[统计口径](calculation.md)。

## 本人模型目录与密钥复用

模型使用、聊天和生图采用同一令牌适配器。一次普通目录查询，冷缓存为 4 次上游请求（当前令牌、完整密钥、读取后的令牌核对、模型目录），热缓存为 2 次（当前令牌、模型目录）；不包括入口会话验证和生图所需的额外路由检查。

密钥只保留在进程内，20 分钟不滑动续期，最多 256 条。缓存按上游、用户、调用凭据和令牌指纹隔离；每次仍检查当前归属、状态和限制，不缓存授权结论。并发读取同一个密钥只执行一次敏感读取，网络请求不占全局缓存锁，其他 KEY 不必等待。复制完整 KEY 是独立的显式操作，不等同于读取模型目录。

请求计数和不同 KEY 的并发隔离由 `tests/test_personal_token_provider.py` 与 `tests/test_manual.py` 的虚构上游回归核对，不使用真实模型或生产凭据。

## 聊天恢复与历史存储

新客户端在配置返回后选择恢复协议。服务端声明 `recovery_snapshot` 时，使用
`GET /cockpit/api/chat/conversations/{cid}/sync` 一次取得同一提交高水位的聊天状态、
首批事件、最新运行和文件版本；只有超出首批的事件才继续分页。
文件版本未变时返回 `files: null`，保留客户端已有列表；该聊天产生更高 Memory
上下文版本时才附带最新个人设置。旧服务未声明能力时使用原有接口，不通过失败请求探测。
恢复不会派发、续跑或重发模型请求。失败后的自动查询按指数退避至 60 秒；
有效 `Retry-After` 比这个上限更长时仍按上游等待时间执行，后台页至少间隔 10 秒。

运行租约复用已经验证的事件投影，只对新事件检查状态转换；验证或提交失败不污染已提交状态。
追加事件只统计本次实际写入的文件，不再遍历整个用户目录。流式正文、推理和协议分片
不重写文件列表、完整运行列表及聊天目录；下一非分片事件和中断恢复会刷新这些派生文件。
首次空间预留仍核对完整磁盘占用，事件落盘、同步及 commit 提交顺序不变。

每进程保留最近最多 8 份已验证的只读历史，常驻索引和状态投影合计不超过 8 MiB。
缓存保存事件位置和区块摘要，不保留整份日志正文；因此日志大于 8 MiB 时仍可命中。
翻页只读取所需区块并核对摘要，无新事件的同步不读日志正文；上下文按运行 ID 查找已验证引用。
冷缓存、淘汰或来源变化后仍完整验证；索引及投影本身超过上限时不入缓存。
区块以换行为边界，目标 64 KiB，单条大事件可能使区块更大，但仍受单事件大小限制。
命中前逐次检查当前用户/聊天归属、删除标记、commit 及日志 inode、大小、修改时间和状态变更时间；
源文件替换、修改、权限变化或未提交尾部不能靠缓存绕过。附件删除控制单独读取，不会因命中历史缓存复活。
缓存只在进程内，退出清空，删除聊天立即移除对应缓存；API 和下载响应仍为 `no-store`。

本机虚构大正文日志测量：65 条事件、10,418,559 字节；缓存索引及投影为 27,675 字节。
人为清空进程历史缓存的 7 次只读同步中位数为 217.041 ms，热缓存 21 次为 0.712 ms，
热缓存完整日志重放次数为 0；两条事件翻页读取 400,504 字节，没有重读整份日志。
两组都使用系统文件缓存；结果仅用于比较这条本地存储路径，不代表生产延迟、网络延迟或模型速度。
回归还核对跨进程中断恢复、事件失败不重复提交、额度预留及附件删除兼容。

## 聊天页面与自动记忆

页面增量处理新事件，按运行、消息和工具记录复用节点；未变化的历史、输出列表及附件托盘不重新绘制。
模型输出更新时保留未变化消息、展开项和阅读位置；替换流式消息正文时按消息内文本位置恢复选区。
内容、历史和个人文档不写入浏览器存储，切换账号仍清空私有视图。

默认自动记忆能力不变。仅完整匹配“继续”“好的”“谢谢”“OK”等无事实短回复时跳过辅助提取，
不新增模型请求或提示。其他内容继续检查，不按字数、调用间隔或偏好关键词筛掉信息；
明确要求记住、修改或忘记的信息照常处理。主回答、辅助用量、版本冲突和审计规则保持不变。

## 静态资源重验证

`/cockpit/static/` 的成功资源响应支持 ETag 条件请求，返回 `public, max-age=0, must-revalidate`。
浏览器每次核对版本，相同资源可返回无响应体的 304；文件名未带内容指纹，因此不使用长期 `immutable` 缓存。
登录页、私人 API、文件下载及错误响应仍为 `no-store`，缓存静态源码不等于缓存身份或账户余额。

## 目录查询 HTTP 连接复用

仅本人令牌和模型目录的固定读取入口复用连接，包括显式读取完整 KEY 的单次 POST；
模型生成、一般写操作及独立的会话认证传输不使用这个连接池。
每进程最多 16 条连接，同一作用域最多 4 条，空闲 30 秒或存活 120 秒后淘汰。
作用域包含上游地址与路径、进程角色、用户、凭据摘要和账户/模型调用类别；不保存明文凭据、Cookie 或授权结论。
网络请求不占用全局池锁，等待连接仍计入原请求的 10 秒总期限。
只回收完整且有效的成功响应；错误、断连、超时、未读完、要求关闭或设置 Cookie 的响应均丢弃连接。
失效连接不自动重连重发，包括完整 KEY 的读取；后续显式操作可重新建立连接。

本机 HTTP/1.1 虚构上游匹配测量：120 次顺序查询始终是 120 次请求，
一次性连接为 120 条、中位数 0.187 ms；连接复用为 1 条、中位数 0.093 ms。
此结果只说明回环测试的连接重建成本，不代表公网、TLS、模型速度或 New API 限流上限改变。
身份隔离、并发上限、超时、主动关闭与失效连接由真实本机 HTTP 服务回归验证。

## 渠道目录同步

日常刷新读取当前 `channels` 表，对比监控库库存后只写变化的名称、归属和可见性。
没有变化的渠道不更新 `last_seen_at`，未变化的账本不反复分配新 ID。
库存保留已删除渠道的最后名称、ID 和已知归属；历史费用不因渠道删除而丢失。

完整发现历史日志中已删除的渠道 ID 只在首次成功同步或显式请求时扫描。
成功后保存 `channel_catalog_sync_state.history_discovered`，失败则回滚，不把失败记为完成。
需要重新完整发现时，在统计项目目录执行：

```bash
docker compose exec statistics python -m new_api_cockpit.catalog_sync --full
# 非 Docker：python -m new_api_cockpit.catalog_sync --full
```

此命令同步目录，不重新计费或覆盖月度金额。
普通消费归档查询发现的渠道仍会进入库存，不依赖额外的全量日志轮询。

## 每次检查内部共享当月汇总

每天的多账本检查在同一次调用内读取一份新的本月逐渠道金额，再按各账本当前归属汇总。
该数据只在本次检查中共享，不在不同调用之间复用。
手动检查与 `/cockpit/api/statistics/balance` 每次重新计算本月金额，不采用余额缓存。
历史月份读取逐渠道归档，金额以日志 `quota / 500000` 为准。

## 网页列表与公式详情分离

配置监控库时，浏览器使用 `details=lazy` 请求列表。
列表保留展示字段、报表 UUID 和行号；计算公式保存在不可变详情中，悬浮时按需读取。
同一行的并发悬浮共享请求，关闭后迟到响应不再展示，详情不混入其他查询。

详情按管理员与账本隔离，有效期 15 分钟，每管理员最多保留最近 10 份报表。
创建新快照时清理过期内容；无需额外清理进程或分钟轮询。
过期或不可访问返回 `410`，需要重新查询。
不传 `details=lazy`、或未配置监控库时，API 返回完整列表。
Excel 独立实时查询，不直接拼接网页快照。

明细表和状态提示共用一次筛选、聚合结果；数字格式化器复用，日志链接的时间边界只在本次渲染计算一次。
切换账本或重新查询后使用新数据，不跨报表缓存。令牌和分组选项查询与报表共用渠道包含/排除规则，
保留“全部”、空渠道范围和未知渠道的区别。

## 异常日志路径

正常日志使用 PostgreSQL 聚合快路径。
元数据无法正常转换时，在同一个只读、可重复读快照内回退到游标流式读取，
保留日志金额和请求数；未知的用量类别保持 `null`，不当作零。
此路径只在异常数据时启用，不给正常报表额外增加逐日志 Python 处理。

## 操作记录与目标身份

先按游标读取最多 50 条操作，再只汇总这一页的已发起明细；不扫描或展示待执行名单。
每条记录最多返回三位去重目标用户及准确人数，完整目标按明细游标分页查询。
目标名优先取记录快照；缺少用户名的记录按整页 ID 一次批量读取，不逐条调用 New API 或读取 PAT。
列表、结果计数和目标摘要共用监控库可重复读快照，避免并发执行下一组请求造成同页数据不一致。

## 接口文档

OpenAPI 定义不含站点数据或凭据，每个网页进程只生成一次不可变 JSON。
访问接口描述仍逐次验证管理员身份；缓存定义不等于缓存权限、余额或业务响应。
在线调试在初始化时编译本站允许调用的路径，发送时复用匹配规则，不重复展开整份契约。
完整参考的 Scalar 包仅在打开参考页签时加载，日常统计和管理页面不加载它。

## 启动迁移与调度连接

监控迁移在应用启动时执行，普通规则请求只检查迁移版本，不重复建表。
余额和配额调度各持有独立长期会话领导连接，网页子进程可以待命；任务到期才执行业务查询。
健康检查核对线程与领导锁，不查询用户额度或消费，不触发报警。

应用目前使用直接数据库连接，不使用数据库连接池。
Excel 在同步请求中生成，通知由检查/测试调用直接发送；没有异步导出队列或通知任务队列。
数据量较大时，优先缩小查询区间。列表精简减少的是响应体和详情加载，消费聚合仍需访问所选区间的日志。

## 验证

按[贡献指南](../CONTRIBUTING.md)在隔离 PostgreSQL 和虚构数据上运行回归测试。
测试覆盖无变化目录刷新、归档金额保留、公式详情权限/有效期、精简列表不携带公式、
迁移幂等与数据保留、调度领导者接管及退出。测试不代表生产延迟或容量承诺。

## 渠道质量查询

默认近 24 小时，最长 31 天；单个模型/渠道组合原始样本由 PostgreSQL 计算分位数，不平均已有 P95。
源日志 CTE 在同一只读快照中共享，费用与调用分开聚合，避免重试事件重复计费。
页面只查询汇总，小时趋势和请求 ID 样本由 `trends` 接口按需查询；没有自动刷新或新增后台任务。查询、异常 JSON 回退和结果数量均有上限，见[渠道质量](quality.md#数据库和查询边界)。
性能健康不增加网络请求或日志扫描：平均延迟在现有聚合中累加有效耗时，高频模型合并未截断的渠道结果，最多显示六个。
默认查询只读取当前启用渠道；只有 `channel_status=all` 的历史查询才读取监控库存，补充已删除渠道的信息。

## 流式模型测试

智力测试占用当前 Web 请求线程，同一用户通过监控库 advisory lock 避免并发修改专用 KEY。
生成使用流式请求，最长 300 秒，不因持续输出重置总时限；不进入后台队列，也不缓存或保存结果。状态和文本由同一个响应推送，不新增轮询或 New API 请求。超时可能已经计费，前后端均不自动重试。
预览的固定尺寸脚本每个进程只加载一次；页面通过尺寸消息调整沙箱画布，不轮询模型或重新生成。
输出 Token 上限交给 New API 和上游；响应体和 HTML 大小保护见[智力测试](intelligence.md#流式生成与边界)。
