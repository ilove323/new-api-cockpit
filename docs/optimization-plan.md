## 不变的规则

- 不更改计费日志、金额或余额统计口径，不自动重发有副作用或收费的请求。
- KEY 管理保留手动查询，以及每次修改前、后的实时查询；不加二次确认或插件冷却。
- 认证与权限不跨请求缓存；同一请求内允许复用已经验证的数据。
- 不把用户密钥、密码或私有站点清单写入源码、日志和公开文档。
- 存储优化不能复活已经删除的附件，不能把新事件交给不兼容的旧版本写入。

## 上游依赖

KEY 配置的完整 PUT 会覆盖剩余额度。单纯增加查询不能消除并发扣费竞态。彻底修复需要 New API 的局部更新或条件更新能力；在没有确认上游支持前，不宣称该风险已经解决，也不以二次确认替代修复。

本轮核对的官方源码快照 `34003e9c2eed2c20e617f583fdfe54bf1bf42237` 中，
[控制器](https://github.com/QuantumNous/new-api/blob/34003e9c2eed2c20e617f583fdfe54bf1bf42237/controller/token.go#L402-L474)
仍接收完整剩余额度，
[模型更新](https://github.com/QuantumNous/new-api/blob/34003e9c2eed2c20e617f583fdfe54bf1bf42237/model/token.go#L312-L319)
仍将其绝对值写入；据此判断并发扣费窗口未消除。本轮不修改上游源码或站点 New API。

现有跨用户管理适配器还使用 owner 旧 PAT；上游退役后需单独处理替代协议，不能为恢复管理能力而绕过上游退役或暗中创建新式用户凭据。

## 清理与复用结论

- `manual.py` 直接引用当前令牌集成模块；原个人令牌及图片入口保留为指向同一模块对象的兼容别名，无第二份业务实现。已有导入/替换依赖和边界回归，不能按“旧文件”直接删除。
- 报表、选项和异常日志回退已共用 `report.scoped_sql`。保留全部渠道、空范围和未知渠道的语义差异，不把质量查询等不同统计口径强行并入一个构造器。

## 执行顺序

1. 正确性、认证和部署模板：小范围改动及对应回归。
2. 请求次数：记录冷/热缓存、并发和恢复请求预算，再合并重复路径。
3. 聊天性能：存储和页面分开验证，保留旧历史和中断恢复。
