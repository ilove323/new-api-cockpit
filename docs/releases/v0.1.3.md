# New API Statistics 0.1.3

本版本新增管理员配额管理与按用户组定时增减，升级请求历史价格统计，并统一表格金额展示。
**仍必须依赖已部署、使用 PostgreSQL 的 New API。** 发布流程不会自动部署服务器。

## 用户配额管理

- 新增独立 `/quota/` 管理页面，与 `/statistics/` 使用路径链接互跳，保留当前域名、协议和端口。
- 展示用户显示名、用户组、启用/禁用状态与额度；默认仅显示启用用户，可多选状态并按用户组批量选择。
- 先预览，再按每人金额增加或减少额度。通过 New API 官方原子增减接口执行，不直接写用户表，也不以预览值覆盖最新余额。
- 不限制总选择人数。每组最多 5 人并发，等本组全部返回后再发下一组；失败或结果不明确时停止后续组，已成功的操作不自动回滚。
- PAT 从当前管理员的 New API 用户记录读取，仅在服务端使用；无需在 `.env` 配置 PAT。

## 定时额度修改

- `/quota/` 右上角齿轮提供“定时额度修改”和“执行记录”。可多选用户组，设置每位用户增减金额、周期及启用状态。
- 执行时间为北京时间每天 00:00、每周一 00:00、每月1日 00:00。新建或重新启用规则从严格晚于保存时间的下一周期开始，不立即执行。
- 按执行时组内启用且未删除的用户计算，去重后按 5 人一组处理；冻结规则并保存逐用户结果，记录支持分页。
- 普通管理员管理自己的执行规则，超级管理员可管理全部规则；保存后绑定当前操作管理员，执行时重新检查账号状态、权限与最新 PAT。
- 独立、可选的 `quota-worker` 使用 PostgreSQL 单调度器锁和配置变更通知，不在 Gunicorn 内启动计时任务，也不改变余额监控每天 10:00 的检查时间。
- **不自动补发错过周期的额度，不重试结果不明确的请求。** 启动延迟超过 5 分钟会记为未执行。中断后的请求中状态转为结果不明确，未发起请求不续跑。
- 不同规则命中同一用户会累计增减；减少额度可能产生负余额，请先复核用户组、金额和管理员权限。

## 历史价格与展示

- 从消费日志还原请求当时的单价，兼容旧倍率计费和支持的表达式计费。相同历史价格合并，不同历史价格分行；无法还原时不借用当前价格。
- 历史价格能唯一匹配当前档位时显示当前档位名，否则显示 `-`。倍率不作为分行条件；仅在分组倍率发生变化、档位可匹配且有有效解时进行缓存读 Token 数学配平。
- 实际消费始终取日志，原始日志和归档金额不改写。金额详情保留 Token、单价、倍率、试算与实际金额的核对信息。
- 所有页面表格的金额与单价固定显示两位小数；计算、API、Excel 与悬浮详情仍保留原精度，逐行显示值相加可能出现分位尾差。
- 增加前端回归检查和定时调度 PostgreSQL 集成测试，修复原有 Ruff 格式检查问题。

## 升级步骤

升级前备份独立监控库、部署配置及通知加密密钥，并记录旧镜像版本。
**不要清空数据库，也不要把监控迁移执行到 New API 原库。**

1. 更新发布附带的 `compose.release.yml`，保留自己的私有配置和网络设置。将 `.env` 中 `IMAGE_TAG` 设为 `0.1.3`。
2. 确认只读账号可读取兼容文档列出的字段，尤其是 `users.access_token`、`users.group`、`logs.other`、`logs.group` 和 `options`。
3. 如尚无独立监控库，按监控文档建库并设置 `MONITOR_DATABASE_URL`；仅手工配额不要求监控库，定时配额必须配置。
4. 拉取镜像并对已配置的监控库执行增量迁移：

```bash
docker compose -f compose.release.yml pull
docker compose -f compose.release.yml run --rm --no-deps statistics \
  python -c 'from new_api_statistics.balance import initialize; initialize()'
docker compose -f compose.release.yml up -d statistics balance-worker
```

迁移 `007_quota_schedules.sql` 新增以下四张表，并通过 `schema_migrations` 记录，
不清空已有设置、报警、月度归档，也不改变 New API 数据库结构：

- `quota_schedule_rules`
- `quota_schedule_rule_groups`
- `quota_schedule_runs`
- `quota_schedule_run_items`

没有配置监控库时跳过上述迁移命令，并只启动 `statistics`。
如需要定时配额，显式启动可选 worker；普通 `up` 不会自动启用它：

```bash
docker compose -f compose.release.yml --profile quota-schedules up -d quota-worker
docker compose -f compose.release.yml --profile quota-schedules ps
docker compose -f compose.release.yml logs --tail=100 statistics quota-worker
```

未创建并启用规则时，不会因升级修改用户额度。启动后由管理员在页面配置规则。
`statistics` 与 `quota-worker` 必须使用同一版本镜像。

首次使用配额页面时，按 Nginx 示例加入 `/quota` 和 `/quota/` 转发，保留 New API 原入口与 `/statistics/`。
已配置该入口的部署无需新增端口或 location。

回退前先停止 `quota-worker`，再恢复旧应用镜像和 Compose 配置；`007` 仅增加表，可保留新表及执行历史，不需要清空监控库。
任何已发出的额度请求都不能靠停止进程或回退镜像撤销；结果不明确时先核对 New API 额度与审计日志。
