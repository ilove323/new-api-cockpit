# 用户、令牌管理与操作记录

`new-api-cockpit` 在统一 `/cockpit/` 前缀下提供四个页面，以相对路径侧边栏切换。

| 页面 | 职责 |
|---|---|
| `/cockpit/statistics/` | 用量、账单、预算与告警 |
| `/cockpit/users/` | 用户资料与配额合并管理，最后一列放用户操作 |
| `/cockpit/keys/` | 仅 KEY 配置管理，用户列纵向合并 |
| `/cockpit/operations/` | 用户、KEY、手工配额、规则修改及定时执行的统一分页记录 |

## 页面与操作

- 用户管理显示用户 ID、用户名/显示名、用户组、启禁状态、余额、已用金额、KEY 数量及备注。
- 最后一列支持编辑用户名、显示名、用户组、备注，重置密码、启停与软删除；新建用户仅限超级管理员，创建普通用户。
- 用户配额保留按组选择、预览确认与五人并发原子增减，不通过资料编辑覆盖余额，见[用户配额](quota.md)。
- 令牌管理每个 KEY 一行，同一用户的第一列通过 `rowspan` 合并，显示归属用户与新增 KEY 操作；用户资料与余额在用户管理页操作。
- 按用户分页，同一用户的所有匹配 KEY 一次读取，不把用户拆到两页，也不截断用户的 KEY 数量。仅列出拥有匹配 KEY 的用户。
- 默认用户状态为启用，KEY 状态全选；用户组、KEY 分组和状态支持多选，选项搜索按字面关键词匹配，不使用正则或通配符。
- 多选筛选菜单点击外部、切换其他菜单或按 Escape 时收起；菜单内勾选和搜索不会收起，也不会清空已选条件。
- 用户名/显示名/ID 命中时展示其全部匹配 KEY；KEY 名称/ID 命中仅展示匹配 KEY。总数区分用户数和 KEY 数。
- 用户管理的 KEY 数量链接仅传用户 ID，在令牌页面查看该用户的 KEY；可取消指定用户筛选，恢复正常列表。
- KEY 列出名称、脱敏 KEY、分组、有效状态、有限或无限余额、已用额度及到期时间，支持新增、编辑、查看复制、启停、删除和限额设置或增减。
- 表格“分组”列的分组名称可点击：展开所属用户可用的目标分组，选中后弹窗显示原组与目标组，确认一次才执行。KEY 列仍为脱敏文本，不承担改组操作。
- 用户组、KEY 调用分组和统计渠道标签互不混淆；空 KEY 分组为“跟随用户组”，`auto` 为“自动分组”。
- 表格金额显示两位小数，计算保留整数额度单位与 Decimal 精度。KEY 限额不等于用户充值。

普通管理员只管理权限范围内用户，超级管理员可管理全站；不能禁用或删除超级管理员。
密码只重置，不读取或保存到审计；KEY 明文只在明确查看后显示，窗口关闭后清除，不持久缓存。
页面、静态文件和 API 均要求管理员认证，敏感写请求必须是同源 JSON 和对应请求头。

## 使用所属用户 PAT

令牌接口以当前认证用户限定归属。应用先验证实际管理员对目标用户的权限，
再用 KEY 所属用户 ID 读取 `users.access_token`，作为该次官方接口调用的 Bearer。
用户资料管理则使用实际管理员 PAT。

每次接口调用前重新读取 PAT，不缓存、不放到 `.env`、浏览器或监控库。
没有 PAT 时才补建：与 New API 的 `GenerateRandomKey(29 + GetRandomInt(4))` 一致，
使用密码学安全随机字节，标准 Base64 编码；事务锁及唯一约束防止并发覆盖与冲突。
数据库保存 PAT 明文是 New API 原生格式，并按存在的字段补写创建时间。
已存在的 PAT 不更新；用户撤销后，下一次需要凭证的管理调用会重新补建。
列表查询不补建 PAT；打开需要官方接口读取的对象详情可能触发补建。
禁用或已删除用户不会被临时启用，不能用其 PAT 修改 KEY。

**New API 源库的唯一直接写入例外是补建缺失 PAT；余额、密码、KEY、分组等均不通过 SQL 更新。**

### 安装补建函数与最小权限

监控库迁移不会修改 New API 数据库。在 New API PostgreSQL 数据库，
由 `users` 表所有者安装 [source_pat_function.sql](../sql/source_pat_function.sql)，
再仅授予现有源库查询角色函数执行权限：

```sql
GRANT SELECT ON TABLE public.users, public.tokens, public.logs, public.options, public.channels TO cockpit_reader;
GRANT EXECUTE ON FUNCTION public.statistics_ensure_user_pat(bigint,bigint,text) TO cockpit_reader;
```

角色名仅为通用示例；不要给查询角色授予 `UPDATE users` 或 `UPDATE tokens`。
函数为受限 `SECURITY DEFINER`：固定 `search_path`，显式访问 `public.users`，
校验管理员/目标用户角色与状态，只在 PAT 为空时更新相关字段；已撤销 PUBLIC 执行权限。
该函数调用能力只交给受信任的应用服务，不开放给普通用户数据库连接。
普通查询仍使用只读事务，函数调用单独使用可写事务，但角色不拥有直接表写权限。
没有安装或授权函数时，已有 PAT 的操作可使用；缺失 PAT 时明确报错，不尝试扩大数据库权限。
不同版本或 fork 应先核对 PAT 字段和生成规则，不支持只保存哈希且无法回读的 PAT 存储格式。

## 批量改 KEY 分组

选择当前页 KEY 或全部筛选结果，指定一个目标组，先预览再确认。
来源组可多选，目标组只有一个；目标必须对各 KEY 所属用户可用。
预览在监控库冻结具体 KEY ID、所属用户、原组和状态，有效期 15 分钟；
确认前不创建 PAT、不修改 KEY，也不进入操作记录。预览最多展示 100 条，执行使用完整冻结名单。

确认后浏览器每次发送一个请求组，服务端最多 5 个并发。收齐当前组结果后再发下一组。
执行前重新校验实际管理员、用户、KEY 归属及原组状态，不将后来新增的 KEY 纳入名单。
失败、冲突或结果不明确停止后续组，不自动回滚成功项或重试未知项。
监控库先记录请求中再发送，浏览器中断后未发出的组不会自动续跑。
记录中的“请求中”如遇进程中断，应人工核对 New API 审计及实际数据，不直接重新提交。
整个操作没有 100 个 KEY 的总量限制；100 仅为查询分页的最大页大小。

### 并发消费限制

**New API 的令牌 PUT 为配置和剩余额度覆盖更新，没有本功能需要的原子额度增减接口。**
应用会在写入前从官方接口读取最新配置，保留未修改的字段，不写 `used_quota`；
但这不能消除读写之间的并发扣费。因此改组、编辑或调整 KEY 额度前，必须先暂停这些 KEY 的并发调用。
页面和确认窗口会明确提示；不会把“增加/减少”宣传为原子操作。
用户账户的原子增减使用 `/cockpit/users/` 的配额接口，见[用户配额](quota.md)。

### 单个 KEY 快捷改组

点击“分组”单元格时，`GET /cockpit/keys/api/token/<id>/groups` 校验管理员对所属用户的权限，
只从数据库读取当前分组与可选组，不调用上游接口、不补建 PAT、不生成操作记录。
菜单支持关键词搜索，当前组不可重复选择；跟随用户组与自动分组保留原有语义。

选择目标后显示一次确认弹窗；取消不发送变更。确认使用现有
`POST /cockpit/keys/api/token/<id>/action`，仅传 `action=group` 和目标 `group`。
服务端重新验证权限与分组可用性，读取最新 KEY 配置后保留未修改字段，通过所属用户 PAT 调用官方接口，
实际请求进入统一操作记录。
执行中禁止重复提交；失败、网络中断或结果不明确不会自动重试，须关闭窗口、刷新并核对实际结果。

## 统一操作记录与数据库

写操作需要 `MONITOR_DATABASE_URL`。监控库存储：

| 表 | 内容 |
|---|---|
| `user_management_operations` | 实际管理员 ID/名称、操作类型、无凭据参数、状态、确认及完成时间 |
| `user_management_operation_items` | 已发起请求的用户或 KEY ID、归属用户 ID、允许记录的前后配置、逐条结果 |
| `user_management_operation_targets` | 内部待执行名单，用于批量预览/分批执行；不是操作记录 |

独立 `/cockpit/operations/` 页面分页汇总用户与 KEY 操作、PAT 补建、手工额度增减、定时规则修改及执行记录。
普通管理员只查看自己发起的操作，超级管理员可查看全部；列表和逐条详情使用同一权限边界。
管理操作直接读取上述两张表，定时执行直接读取 `quota_schedule_runs` 和 `quota_schedule_run_items`，不复制或覆盖历史。
手工请求先记录再发送；定时规则保存与审计在同一监控库事务内提交。
浏览器五人一组请求时，每组是一条手工记录；未曾保存的历史手工操作不会补造。
操作记录只保留已发起的成功、失败、冲突、结果不明确和请求中状态，不显示或保存未发起明细。
预览名单放在独立内部表，发送前同一事务写入“请求中”明细并移除对应名单；终止后删除剩余名单。
没有已发起明细的预览或定时任务不出现在记录页；过期预览在创建后续预览时清理。上游看到的是 PAT 所属用户身份，
我们的审计额外保存实际管理员身份；不存密码、PAT、完整 KEY 或原始远端响应。
所有用户、KEY、PAT 和额度操作在操作列及详情标题显示目标用户名与用户 ID，KEY 操作显示其所属用户，
不把发起管理员当作操作目标。批量操作按用户 ID 去重，列表最多展示三位用户及实际已发起的用户总数，
详情按每条用户或 KEY 请求展示完整目标身份，保留分页；未发送的对象不计入目标名单或人数。
定时规则的新增、编辑、启停与删除显示规则 ID 和目标用户组，定时额度执行显示实际已发起请求的用户，
保存规则不冻结将来的组内成员。规则删除也保存用户组快照。
新记录保留目标用户名快照；已有记录优先读取已有快照，缺失时按明细用户 ID 一次批量查询当前用户名，
查不到时仍显示用户 ID，不改写历史记录，也不为显示记录生成 PAT。
该信息保存在操作参数、明细 JSON 及定时执行快照中。
新建对象的官方接口不返回对象 ID 时，内部目标 ID 为 0，界面明确显示“ID 未返回”；
新增用户显示请求中的用户名，新增 KEY 显示已知所属用户，均不以管理员 ID 代替新对象。
没有监控库时只支持查询，拒绝没有审计的写操作。升级不清空用户、KEY、账本、归档及定时规则。

### 操作记录接口

网页管理员 Basic Auth：`GET /cockpit/operations/api/records`。
可选 `kind=user|token|quota|schedule`，后续页传回响应中的 `next_before` 作为 `before`；
游标同时包含时间、来源和记录 ID，不使用单一时间戳翻页。
明细为 `GET /cockpit/operations/api/records/<source>/<record_id>?after=<target_id>`，
`source` 为 `management` 或 `schedule`，下一页使用 `next_after`。
这些接口只读，不触发原操作再次执行。
