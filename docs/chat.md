# AI 助手：多协议、联网、长期记忆与工作上下文

本页描述当前源码；站点功能总开关 `CHAT_ENABLED` 默认关闭，启用后还须启动聊天请求池。
上传上限为 50 MiB（界面显示 50 MB），通过发送按钮旁的“上传附件”选择文件，或拖入输入区；空页面会自动新建聊天。升级时须同时更新应用和 Nginx 请求体上限。
公共文档不代表任意站点的部署状态。**部署和健康检查不等于真实渠道生成/计费已联调**，真实渠道、能力和搜索服务需按站点单独验证。
页面 `/cockpit/chat/`，个人设置 `/cockpit/chat/settings/`。只使用当前账号自己已有的 KEY，不创建 KEY、不换组、不改额度。
实现边界见[聊天开发说明](chat-internals.md)，开发验证入口见[贡献指南](../CONTRIBUTING.md#ai-助手离线回归)。

## 使用与隔离

1. 打开聊天页即可输入消息，不要求上传附件或先点击新建。选好 KEY 和模型后，首次发送会自动新建聊天，再提交正文；创建失败保留草稿、不自动重发。输入后再添加附件也不会丢失正文。发送按钮只显示“发送”。页顶的 KEY、模型独立于聊天，选好一次后当前账号在此浏览器中沿用，新建/切换/删除聊天不重置。刷新后自动恢复选择，并重新校验本人 KEY 和当前模型目录；目录读取不生成回答。缓存仅含 KEY 的数字 ID、模型名和内部兼容标记，不含 KEY 密文、掩码、目录、聊天正文或个人文档。失效 KEY/模型不会自动换成其他项，需重新选择。
2. 每次只生成 **一个回答**，不再提供候选数或上下文策略选择。上下文固定自适应；自动 Memory 默认启用，切换聊天或刷新后不用重新开启。
3. 聊天页不再提供 Skills 按钮或模板窗口；已有聊天的已载入模板保持不变，发送、刷新或重新登录不清空。个人设置仍可管理模板库。界面不区分普通聊天和 Agent。默认读取本轮引用附件的正文，文件操作、联网、自适应上下文与自动 Memory 统一提供；工具由模型按需调用。搜索未配置不影响网页抓取/文本下载。
4. 模型请求按实际用量计费。摘要、压缩和自动记忆可能产生有上限的独立辅助请求，实际次数与用量在运行记录中分别显示。模型选择区域不再显示能力/计费/默认设置的说明，也没有“管理我的 KEY”链接或折叠替代区；KEY 管理仍可从侧栏“我的令牌”进入。站点明确禁用的能力不会被强行开启。API 的旧参数与历史多候选仍兼容，当前页面不再创建多候选。
5. 刷新、断线、重新登录、查看历史或撤销 Memory **不重新生成、不续跑、不自动重发**。运行状态自动查询，失败后退避，并遵守上游返回的等待时间。新版服务合并状态、首批事件和文件版本查询，文件未变时不重复返回列表；历史超出首批仍完整分页。聊天页不再单独提供“只读刷新状态”按钮。回答底部保留实际状态、模型和用量，移除“查看上下文”按钮及固定的上下文/自动记忆/联网说明。停止不能撤销已发生的费用、文件或 Memory 写入。

- 用户、管理员、超级管理员均只能访问自己的聊天、文件和设置，没有管理员代查入口。
- 模型目录与连续工具请求复用服务器进程内的密钥，避免反复读取密钥触发 New API 的敏感操作限流。复用窗口为 20 分钟、不随请求延长，每进程最多 256 条，按站点、用户、登录凭据和令牌隔离，不写入浏览器、文件或 Redis。每次仍读取令牌当前归属、状态和限制，模型请求继续由 New API 校验；撤销、禁用和修改模型限制不会被缓存放行。遇到 429 显示请求过频，不再提示权限错误，也不自动重试。
- 一个聊天的文件工具不能读其他聊天；上传原件只读，输出保留所有版本。历史归属绑定用户 ID，不绑定 KEY、用户名或浏览器。
- 列表及事件都完整分页。空、失败、取消、中断和待修复记录保留可见；历史未加载完整时不能发送，避免用缺页历史继续。
- 每用户最多 200 个聊天，超限不自动清理。单机默认同时 2 轮、每用户 1 轮，不排队。
- 单个附件最多 50 MiB（52,428,800 字节，包含边界值），支持文本、PDF、Word（doc/docx）、Excel（xls/xlsx）及 PNG/JPEG/WebP/静态 GIF/BMP；文本输出与 URL 下载最多 64 KiB，生成的二进制文件最多 4 MiB。不解压用户压缩包，不执行 HTML、代码、脚本、Office 宏或公式。没有当前聊天时选择文件会先新建聊天再上传，不要求先选 KEY/模型，也不会发起模型调用；有运行、存储待修复、配置未读入或登录失效时仍禁止上传，并显示原因。

### 附件与输出

- “上传附件”位于发送按钮旁，可一次选择多个受支持文件，或拖入输入区；仍逐个上传，整批先检查类型、单文件大小和本轮引用数量。
- 上传成功即作为本轮引用，以文件卡片显示在输入框里。卡片的 × 仅取消本轮引用；“删除”会真正删除服务器原件。上传未确认时不自动重传或引用；已保存的文件通过只读恢复后可手动引用。
- 发送被服务器确认后，附件移入对应用户消息；可点击文件名下载，或点击“引用”加入下一轮。不修改历史消息或重新上传。未发送过的上传文件显示在聊天区“已上传附件”中，刷新后仍可选择；未发送的引用选择本身不写入浏览器。
- 输入框附件卡片、已上传附件及历史消息中的附件都有“删除”按钮，确认后立即取消引用并删除原件；不要求选择 KEY / 模型。生成回复时也可以删除，不等待该轮结束、不自动取消或重新发起模型请求。
- 已发送附件删除后，历史保留文件名及“已删除”标记，不再提供下载/引用；未发送附件直接从输入框和未使用列表移除。删除不改写旧消息与原有事件，重复删除安全。删除意图先持久化，再移除文件；进程中断后恢复会完成清理，刷新不会复活附件。
- 删除不能撤回已发给模型、已下载、当前回复已读入的内容，也不抹除历史回复、工具结果或备份。后续轮次不再读取已删原件，并跳过删除前或删除时在途轮次产生的上下文缓存；需要重新使用时重新上传并引用新文件。永久保留的文件元数据仍计入每聊天 200 个文件记录的安全上限，文件本体空间会释放。
- 右侧“输出内容”只列当前聊天生成的文件，最近生成的在前，同名各版本保留；整行可点击下载。上传原件不混入输出列表。下载沿用本人会话鉴权和文件 ID，不打开接口返回的任意外链。

### 生成可下载文件

直接在聊天中要求“生成 PDF 报告”“导出 Word 文档”“做一份 Excel”或“画一张 PNG 示意图”。助手调用 `write_file`，服务器生成并重新解析真实文件；成功提交后出现在右侧“输出内容”，点击整行下载。不生成假链接，不把 Markdown、JSON 改扩展名当成文件。

| 输出格式 | 生成方式 |
|---|---|
| PDF（.pdf） | Markdown 正文排版为标准 PDF，支持中文嵌入字体、分页、标题、列表、加粗及表格。 |
| Word（.docx） | 生成可编辑的 Office Open XML 文档，含标题、段落、加粗及表格。不是 HTML 伪装的 .doc 文件。 |
| Excel（.xlsx） | 生成真实多工作表工作簿，保留数字、布尔值、文本和显式的本表公式。不是 CSV 改名。公式不在服务器计算，由 Excel 打开时计算；普通字符串即使以 `=` 开头也不执行。 |
| 图片（.png / .jpg / .jpeg / .webp） | 将画布中的文字、矩形、椭圆和线条渲染为对应编码的真实像素图片，可用于图表、流程与示意绘图。不是摄影文生图模型；写实生图使用生图工作站。 |

`write_file(name, content)` 的调用格式：

- PDF / Word：`name` 用 `.pdf` / `.docx`，`content` 为 Markdown 正文；表格最多 8 列、每格 200 字。
- Excel：`name` 用 `.xlsx`，`content` 为下面 JSON 的字符串形式。支持最多 20 个工作表、共 2 万个单元格；显式公式限本表四则运算及 SUM / AVERAGE / MIN / MAX / COUNT / COUNTA / ROUND / ROUNDUP / ROUNDDOWN / IF / ABS，不允许外部链接、宏或 DDE。

```json
{"sheets":[{"name":"预算","rows":[["项目","金额"],["研发",42],["合计",{"formula":"=SUM(B2:B2)"}]]}]}
```

- 图片：`name` 用对应图片后缀，`content` 为下面 JSON 的字符串形式。宽高各 64–4096，合计最多 800 万像素，最多 500 个元素，颜色为 `#RRGGBB`。`text` 使用 `x/y/text/size/color`；`rect/ellipse` 使用 `box/fill/outline/width`；`line` 使用 `box/outline/width`。不接受代码、外链、文件路径或任意 SVG / HTML。

```json
{"width":800,"height":500,"background":"#FFFFFF","elements":[{"type":"text","x":30,"y":20,"text":"预算示意图","size":28,"color":"#172033"},{"type":"rect","box":[30,100,210,400],"fill":"#2563EB"}]}
```

内容描述最多 64 KiB，真实二进制最多 4 MiB；生成进程限 15 秒，随后执行有界格式解析。不会执行模型提供的代码、宏、HTML 或下载远程资源。生成或校验失败不会发布正常输出条目。相同调用 ID 不重复生成；同名的后续调用保留新版本，原件及旧版本仍可下载。生产镜像包含中文字体和生成库，升级无需改 Nginx 或数据库结构。回退必须使用支持二进制输出记录的兼容镜像，不能直接启动旧的纯文本记录读取器。

### 文档与图片如何读取

| 格式 | 读取方式 |
|---|---|
| PDF | 提取各页文字；无文字的扫描页附带页图，交给支持视觉的模型读取。文字页中的插图不单独渲染。 |
| docx | 提取正文、表格、页眉页脚，以及受支持的内嵌图片；不访问外链，未解析的嵌入图形会注明。 |
| doc | 使用运行镜像内的 Antiword 提取正文，不运行 Office、宏或嵌入对象。 |
| xlsx / xls | 提取工作表及单元格；xlsx 公式显示表达式与现有缓存值，无缓存明确注明；xls 使用已缓存的计算结果。不重新计算公式，也不执行链接、宏；图表和嵌入对象不解析。 |
| 图片 | 校验真实格式、像素及静态帧，按方向信息归正并生成有界 JPEG 视觉输入；传输图最长边 2048，不携带 EXIF。上传原件及下载内容不改变。 |

文档解析在无凭据的独立进程中进行，生产环境限制时间、CPU、内存和输出；OOXML 检查 ZIP 大小、路径及 XML 实体。解析异常、加密、损坏或格式伪装在上传时明确拒绝，不留下“已上传但不能读取”的正常文件条目。

安全上限包括：单次解析 20 秒、文本 2 MiB、PDF 200 页、Excel 20 万个单元格、图片 2000 万像素，当前及历史引用合计最多 8 张视觉图；大量扫描页或复杂文档需拆分。上传 50 MiB 不代表模型能一次接收全部内容。引用超出上下文或请求大小时在派发模型前拒绝，不截断、不隐藏重试。

图片、扫描 PDF、含内嵌图片的 Word 需要所选模型实际支持视觉。不会因为目录未声明视觉能力就禁用模型，但渠道实际拒绝图片时会显示真实错误，不擅自换模型或再次收费。自动 Memory 仍以用户明确陈述为来源，不把附件中的内容自动当作个人事实。

## 模型协议与公开推理

支持固定 New API 上游的 Chat Completions、Responses 和 Anthropic Messages，不接受用户自定义模型 URL、认证头或代理。
协议来自本人模型目录的明确元数据或运维能力配置，不按模型名称猜测。模型列表只按聊天协议和权限判断是否可选，不因缺少工具声明禁用模型。已确认聊天协议的模型默认提供受控工具，不要求逐个填写工具白名单；运维明确配置 `tools:false` 时仍遵守，但附件正文读取不受影响。模型或网关实际拒绝工具参数时显示真实错误，不自动重试、切换协议或再次收费。

### 附件正文与按需工具

- **引用附件**：上传后自动加入输入框的本轮附件，也可从历史消息或“已上传附件”中再次引用。服务器校验原件哈希及当前用户/聊天归属，读取文本或解析文档，将正文和必要的视觉图作为资料交给模型。这个步骤不依赖模型发出工具调用，也不需要逐模型开启读取权限。
- **文件与联网工具**：与附件正文同时可用。助手可按需检索当前聊天文件、分段读取、创建输出版本或访问受控公网，不需要切换模式；工具执行仍发生在服务器，不是模型直接访问磁盘。
- 未加入本轮附件的文件不会在请求准备阶段自动塞入正文；模型按用户任务需要时可通过文件工具读取。文件正文是资料，不是新的指令、系统消息或权限。原件及输出版本不可变，后续按历史引用的同一原件重建上下文；正文不重复保存进事件日志，不跨用户、跨聊天读取。
- 上传仍为单个附件最多 50 MiB，但不代表模型能一次接收 50 MiB。正文、个人设置和历史计入上下文预算；图像使用独立的上下文预留，Base64 传输展开仍受请求字节硬上限限制，实际 tokens/费用按供应商返回记录。本轮引用超限在调用模型前返回 `413`，不截断或额外调用摘要模型来掩盖。可拆分文件、减少本轮引用，或取消引用、让助手按需检索文档文字；图片视觉读取仍需引用。
- Chat 保存上游实际返回的 `reasoning_content` / `reasoning`；需要这些字段的工具连续调用会回传对应字段。
- Responses 保存并按协议重放 reasoning、function call/output 和消息阶段，使用 `store:false` 及所需的 encrypted reasoning 连续状态。
- Anthropic 工具循环保留完整 thinking、signature 和 redacted blocks，不把它们转成 Chat 的 `tool` 消息硬塞。
- 页面折叠显示实际公开返回的推理**文本或摘要**。签名和加密状态不作为“隐藏思考原文”展示，也不尝试解密或编造。
- 不透明连续状态绑定协议、模型、本人 token ID 和能力版本；切换后从可读原始历史重新构建，不跨模型/令牌硬塞。

协议/参数失败后不自动切协议、换 KEY、降级或重试。离线兼容测试不能保证任意网关和供应商配置都可用。

## 受控联网与当前聊天原文

文件工具中的 `list_files`、`read_file`、`search_files`、`write_file` 四工具保持独立工作区边界。
当前界面默认提供以下联网工具，API 仍以 `web_enabled` 明确传递，遵守站点禁用项和网络安全限制：

| 工具 | 行为与边界 |
|---|---|
| `web_search` | 访问运维配置的 SearXNG JSON 搜索后端，最多 5 条来源；未配置就明确返回不可用，不偷偷抓搜索结果页 |
| `http_fetch` | 公网 HTTP(S) GET；UTF-8 文本/HTML 正文提取，去除脚本/样式等噪声，保留来源与截断标识 |
| `download_url` | UTF-8 文本下载到当前聊天的不可变输出版本；文件名不能指定宿主路径，来源 URL 随工具结果保存 |

公网工具不转发 Cookie、KEY、Authorization 或环境代理；DNS 全部地址校验后固定数值地址连接，TLS 校验原域名，每一跳重定向都重新校验。
拒绝内网、环回、链路本地、云元数据、特殊 IPv6、非标准端口、用户凭据 URL 和 HTTPS 降级。单工具最多 15 秒、响应最多 2 MiB、返回结果最多 32 KiB、最多 3 跳重定向，并受整轮截止/取消控制。
不承诺可抓取需要登录、反爬、压缩正文或非 UTF-8 编码的网站。完整规则见[公网工具约束](chat-internals.md#文件与公网工具)。

自适应 Agent 另提供 `search_chat_history`，只检索本人**当前聊天**的原始公开文本和有界工具资料片段，可分页定位原事件；不是跨聊天或跨用户搜索。
网页、检索结果、文件及工具输出都是不可信资料，不授予额外权限，也不自动升级为长期用户事实。

## Skills、MEMORY、SOUL、IDENTITY

个人设置页可手工查看、编辑或清空三份文档：MEMORY 保存本人愿意复用的事实/偏好，SOUL 描述风格，IDENTITY 描述助手背景。它们不改变账号权限、真实模型身份或工具能力。
Skill 是单文件提示模板，个人设置中维护模板库；聊天页的模板操作入口已移除，原有会话载入状态和管理 API 保留。载入状态保存于本人当前聊天，不跨聊天自动载入，也不会在发送后清空；移除不删除模板库或历史快照。不读取宿主 Codex 技能库，不安装仓库、不执行 `scripts`。库中模板被删除后，原有已载入引用仍按接口校验，不偷偷跳过。格式见[个人设置与自动记忆](chat-internals.md#个人设置与自动记忆)。

**自动 Memory 与聊天摘要是两回事：**

- 当前页面默认开启自动记忆。正常回答保存完毕，再在同一轮里最多发起一次有界提取调用；有真实辅助请求/用量记录。“继续”“好的”“谢谢”“OK”等完整的无事实短回复不发起提取。除此之外不靠字数、调用间隔或关键词限制检查，明确要求记住、修改或忘记的信息照常处理。没有合格长期事实时不修改 MEMORY，不等于每句话都会永久保存。
- 仅把本轮真实用户消息作为候选事实来源；排除助手、网页、附件和工具输出。新增/更新事实必须逐字对应用户来源摘录，仍不等于事实真实性或长期意图已被独立证明。
- 只能修改 `MEMORY.md` 的版本化受管区，保留手工区；不自动改 SOUL、IDENTITY 或 Skill。受管区格式被手工破坏时停止自动更新，不覆盖修复。
- 先记录变更意向，再按提取时的 context/MEMORY 两个版本 CAS 保存，最后写入完成审计；并发手工编辑优先，失败不换新版本重试。
- 本人可查看来源、前后正文/哈希与版本并显式撤销。撤销也做版本比较，不能覆盖之后的手工或自动更新。
- 提取无合格事实、版本冲突或辅助模型失败会留下提示，不抹掉已保存回答；取消、总截止或存储故障仍按整轮状态收尾。

个人 manifest 与聊天事件不是同一个原子文件：若进程在 Memory 提交后、完成审计前崩溃，保留的意向仅表示结果待核对，**不声称已确认写入，也不自动重放或再次收费**。可通过个人设置版本/哈希与意向核对；只有完成审计支持一键撤销。详细协议见[自动记忆提交规则](chat-internals.md#个人设置与自动记忆)。

每轮个人设置/Skill 的冻结副本仍不可变；之后的手工/自动更新只影响未来轮次。文件工具输出一个同名 `MEMORY.md` 只是普通聊天文件，绝不等于修改永久 Memory。
勿粘贴凭据；识别规则会拒绝明确凭据格式，但不是对所有自然语言秘密的完整 DLP 保证。

## Codex 式上下文管理

完整存档与模型工作上下文分开：

- 放得下且未达到压缩阈值时使用完整可重放历史；失败/中断轮次的用户输入及安全部分文本带不完整标识保留，残缺工具对不会重放。
- 自适应模式接近配置输入预算的 **75%** 时，压缩较早前缀，保留最近两个完整轮次和当前要求/个人设置；Agent 运行内增长也可在后续派发前压缩完整旧工具组。
- 明确配置兼容 `Responses /responses/compact` 才用原生压缩，保存并重放接口返回的**整个窗口**，不是抽取一个加密项。普通 Responses 支持不等于网关支持 compact。
- 其他配置采用严格六类可读检查点：目标、约束、决定、进展、待办和引用。保存来源覆盖与哈希；摘要是模型生成资料，不是新授权或已验证事实。
- 可复用检查点仍须通过来源与四项绑定校验；不兼容时重新规划。原生请求失败后不会再偷偷调用摘要模型重复收费。
- 单轮最多 3 次压缩，压缩和自动 Memory 等辅助调用合计最多 4 次；主调用最多 6 次，全部最多 10 次，整轮最多 180 秒。UI 分用途显示请求数及实际返回用量；缺失用量显示未知，不当作 0。
- 新 UI 默认自适应；兼容的 `recent` 策略按预算取最近完整语义轮次、不调用压缩。无论哪种策略都不删除 UI 历史。

字节预算不是每个模型的精确 Token 窗口估计；运维应保留输出/推理余量。必留消息、超长旧前缀或压缩结果仍超限时明确失败，不静默丢历史，也不无限调用模型。完整契约见[工作上下文与历史](chat-internals.md#工作上下文与历史)。

## 配置与可选请求池

聊天使用同一个应用镜像、独立 `COCKPIT_PROCESS_ROLE=chat` 池，默认端口 8093；不运行迁移、余额或配额定时器。
以下 profile 说明用于[接入已有 New API](existing-installation.md)；[全量部署](deployment.md)使用独立的七服务 Compose，默认已启用聊天池，不需要再合并这套配置。
Compose 的 chat 是可选 profile，原有默认启动不受影响。聊天池通过环境白名单只接收 New API 内部地址和聊天配置，不继承 `.env` 中的数据库或通知凭据。

在 Compose 所在目录准备仅供此实例使用的本地 POSIX 目录，禁止 NAS/NFS、共享多主机副本或软链接：

```bash
mkdir -p ./data/chat
sudo chown 10001:10001 ./data/chat
chmod 700 ./data/chat
```

设置 `CHAT_ENABLED=true`、稳定唯一的 `CHAT_INSTANCE_ID`（如 `site-a`）及 `CHAT_DATA_DIR=/app/data/chat`。
chat 服务 bind mount `./data/chat:/app/data/chat`，源目录缺失应拒绝启动，不回退 `/tmp` 或 chmod777。
Nginx 将 `/cockpit/api/chat/` 转到 chat 池并关闭 SSE 缓冲；页面/静态资源仍走 web，不公开 data 静态目录。
上传路径的 `client_max_body_size` 使用 `51264k`，容纳 50 MiB 文件与 multipart 头；不要放大所有 API、Skill、工具输出或上下文限制。
选择包含聊天组件的 Release，准备数据与配置后执行 `docker compose --profile chat pull`，再执行 `docker compose --profile chat up -d --no-build --pull never`。旧发布镜像不能通过添加 profile 获得新功能；源码构建另见[源码部署](deployment-source.md)。

### 模型能力

能力文件仅能确认本人 KEY 目录内模型，不能添加 KEY 本无权限的模型。v1 配置兼容原 64 KiB 上限；v2 显式设置协议、输出上限、推理参数和压缩能力，输入最多 2 MiB。
示例 ID 是虚构占位值，必须替换并先确认渠道实际兼容：

```json
{
  "schema_version": 2,
  "models": {
    "example-chat": {"protocol": "chat_completions", "tools": true, "stream_usage": true, "max_input_bytes": 65536, "compaction": "summary"},
    "example-responses": {"protocol": "responses", "tools": true, "max_input_bytes": 262144, "max_output_tokens": 8192, "reasoning": {"effort": "medium", "summary": "auto"}, "compaction": "native"},
    "example-messages": {"protocol": "anthropic", "tools": true, "max_input_bytes": 262144, "max_output_tokens": 8192, "thinking": {"type": "adaptive"}, "compaction": "summary"}
  }
}
```

将能力文件只读挂载并设置 `CHAT_CAPABILITIES_FILE=/app/config/chat-capabilities.json`。不是每个 Anthropic 模型都接受 adaptive thinking，也不是每个 Responses 网关都支持 compact；按渠道设置，错误不隐式降级。
`reasoning_effort` 只用于 Chat，`reasoning` 只用于 Responses，`thinking` 只用于 Anthropic。工具 schema 固定，不能透传任意请求参数。

### 搜索后端

可选配置（端点为虚构示例，不附带凭据）：

```dotenv
CHAT_WEB_SEARCH_BACKEND=searxng
CHAT_WEB_SEARXNG_URL=https://search.example.org/search
```

SearXNG 须开放 JSON 查询，端点也必须是标准端口公网 HTTP(S)，不允许用户通过它探测内网；不在此功能中安装搜索服务。未配置搜索不会关闭独立的公网抓取和文本下载，也不会伪造搜索结果。

## 存储、备份与升级

历史、附件、完整原生连续状态、个人快照、工作检查点和 Memory 审计都在本人文件作用域内，不进统计业务数据库。日志按顺序提交，列表/运行索引可重建；个人 manifest 是权威设置提交点，不能当缓存删除。
备份应在停止 chat 写入后覆盖完整 `data/chat`；保留稳定 instance ID。宿主管理员/备份操作者仍可读取磁盘明文，应用隔离不是磁盘加密承诺。

新代码可读取原有 v1 历史；新增字段和事件保持严格白名单。**旧程序不一定理解扩展事件**：降级前须停写、使用兼容版本或恢复升级前一致备份，不可直接换回旧镜像继续写新数据，更不能清空记录规避兼容问题。

## 仍未实现的范围

分享/协作、管理员代查、跨聊天/跨用户全文检索、RAG/向量库、MCP/插件市场、运行时子代理、浏览器/shell/代码执行、Skill 脚本安装、无人值守后台续跑或失败自动重试，均不在本轮范围。PDF、Office 和图片附件已支持，具体格式、扫描页视觉输入及读取限制见前面的“附件与输出”说明；不提供独立 OCR 服务。
本版支持三种模型协议、公开推理内容、按需联网、自动记忆与上下文压缩。当前页面固定单回答，历史多候选仍可读取；具体模型能力以站点配置和上游返回为准。

### 附件删除接口与升级

`DELETE /cockpit/api/chat/conversations/{cid}/files/{fid}`，JSON 为 `{"confirm":true}`，沿用本人登录会话、会话戳、同源及写操作校验。只删除当前用户/聊天的上传附件，不删除输出版本，也不向模型提供删除工具。成功返回含 `deleted_at` 的文件摘要；原件下载/读取返回 `410 CHAT_FILE_DELETED`。缺少确认、越权或跨聊天请求拒绝。

删除状态保存在当前聊天 `control/deleted-upload-<file-id>.json` 中，含文件 ID、原件哈希、所属用户/聊天及删除时间。它是独立的持久控制记录，不是修改原始 `file.added` 事件；发布后才移除 blob。运行接受与删除使用短控制锁，生成中不占用删除操作的长租约；准备期间附件发生变化时，在模型派发前拒绝并要求核对。旧摘要缓存不会跨删除继续复用原件内容。

升级无 SQL 或 Nginx 变更。首次删除后不能直接启动忽略删除标记的旧镜像；使用发布时提供的兼容回退镜像，保留删除感知的存储、上下文和占位显示，仅恢复旧的附件操作界面。常规回退不恢复聊天目录或数据库，避免让已删文件复活。备份仍按独立保留策略管理。
